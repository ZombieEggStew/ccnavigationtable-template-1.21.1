## ① throttle 穿模修复（ControlDesk）

- **现象**（issue 报告）：控制台台面从油门杆（throttle）中穿出，仅 throttle 出现，throttle_2 及任何其他控件正常。
- **定位**：BER 分支实装渲染（`ControlDeskRenderer.renderThrottlePart` / `renderThrottleHandle`）误用了**预览盒专用常量** `THROTTLE_PLACE_Y_BOTTOM = 7f`（注释：下沉 1px 嵌入桌面示意），导致 throttle 模型底部 1px 嵌进桌面顶面（`MODEL_PLACE_Y = 8f`）→ 桌面面片穿透。throttle_2 用 `MODEL_PLACE_Y = 8f` 所以正常；指示灯（indicator）也已用 8。
- **排查过程**：先后两次临时关闭 Flywheel 路径（注释 `CCPeripheralExtenderClient` 控制台 Visual 注册 + 强制 `ControlDeskRenderer.shellInstanced=false`，两处必须同时改，否则 BER 提前 return 控件不显示），进游戏确认穿模出在 BER y=7 分支。
- **修复**：`ControlDeskRenderer` 两处放置底 y `THROTTLE_PLACE_Y_BOTTOM (7)` → `MODEL_PLACE_Y (8)`；两条渲染路径（Flywheel `ControlDeskVisual.applyThrottlePlacement` 本就用 8 / BER 本次修复）现在一致。临时调试改动全部还原。
- **保持不变**：`ControlDeskBlock.throttlePlaceBox` / `ControlDeskPlacementOverlay` 里的 7 是**预览/扳手拆除盒**的刻意下沉 1px 示意，与实装渲染无关，不动。
- 可选后续：模型整体上移 1px 后，拆除命中盒顶 y13 与模型顶 y14 有 1px 差（几乎不可感知），如需可微调 `throttlePlaceBox` 顶 y。

## ② Monitor 天花板挂载（hanging）

需求：monitor 可倒挂贴天花板放置，**只有底座+轴承颠倒，屏幕主体（case）保持正立**（对齐 altitude_sensor 模式，非整体 180° 翻转）。

### 设计要点

- **静态/动态模型划分**（复用现有）：`my_monitor_base.json`（底座，静态）= 翻转对象（blockstate `x:180`）；`my_monitor_bearing.json`（支架/轴承，动态 BER/Flywheel）= 渲染链加 180° X 翻转；`my_monitor_case.json`（屏幕主体，动态）= **完全不动**。
- **收益**：case 不翻转 → 屏幕主体位置不变 → 命中射线、文字方向、pitch/yaw/offset 语义全部保持落地行为，无需改。
- **不需要额外模型**：同一套 json 复用，翻转全部在渲染期完成（blockstate x/y + BER/Flywheel 变换）。
- 翻转是**模型空间最内层**变换（先于 yaw/offset/facing 作用于顶点），保证 bearing 与 case 位移一致；`MonitorTransform.applyHanging` 与 `MonitorBlock.inverseToModel` 的挂顶逆翻转严格互逆（单一来源原则）。

### Step 1：打通（blockstate 8 态 + bearing 翻转 + 碰撞/拆卸/菜单）

- `MonitorBlock.java`：
  - 新增 `BooleanProperty HANGING`（`BlockStateProperties.HANGING`）→ 8 态（正好"多 4 格"）；`createBlockStateDefinition` 注册。
  - `getStateForPlacement`：点击方块底面（`Direction.DOWN`）→ `hanging=true`；facing 语义不变（屏幕主体不翻转，仍朝玩家）。
  - 挂顶选择框 `HANGING_SHAPE`（底座 y14..16、支架 y5..14，case/box_back 不变）+ 挂顶碰撞体 `HANGING_BASE_SHAPER`（y14..16）；`getShape`/`getCollisionShape` 按状态选择。
  - `onSneakWrenched` 底座命中判断按状态区分（落地 y0..2 / 挂顶 y14..16），否则挂顶监视器拆不下来。
- `my_monitor.json`：8 个变体，`hanging=true` 用 `"x": 180`（只转静态底座）。
- `MonitorTransform.java`：新增 `applyHanging`（绕方块中心 X 轴 180°，模型空间最内层）。
- `MonitorRenderer` / `MonitorVisual`：**仅 bearing 路径**加翻转（PoseStack pushPose 隔离 / instance 独立参数），case 路径不动。
- `MonitorOutlineRenderer`：挂顶底座描边 y14..16、轴承描边 y5..14。

### Step 1 踩坑：菜单打不开

- **现象**：挂顶 monitor 空手蹲下右键 / 扳手右键都打不开配置菜单。
- **原因**：`MonitorGridOverlay` 底座命中判定硬编码落地 `localY 0..2/16`（`MonitorBlock.onSneakWrenched` 已修但菜单走的是客户端这套独立判定，漏了），挂顶底座在 y14..16 → `basePos` 恒 null → 菜单条件不成立。
- **修复**：`MonitorGridOverlay` 底座命中判定按状态区分（同扳手判断模式）。

### Step 2：case 下移 2px（双侧补偿）

- **需求**：挂顶后 case 顶部与翻转底座（y14..16）重叠，case 整体下移 2px。
- **为什么不能只改渲染**（本项目铁律：渲染与检测必须严格互逆、单一来源）：case 平移同时影响"可见位置"和"坐标映射"两套坐标系。只改渲染不改命中逆变换 → 屏幕命中面板错位、网格坐标系统性偏 2 行、旋钮拖拽跟踪错位、Outliner 网格线/预览框错位。
- **实现**（新增常量 `MonitorBlock.HANGING_CASE_DROP = 2f`，单一来源）：
  - 渲染侧：`MonitorRenderer` case 路径 + `MonitorVisual` shell/模块 instance 加 `applyHangingCaseDrop`（translate -2/16 Y）；`MonitorOutlineRenderer` 挂顶 case 描边改为"先 pitch 后 drop"。
  - 命中侧：`MonitorBlock.inverseToModel` / `transformPointToLocal` / `intersectScreen` / `rayToScreenLocal` / `rayToGrid` 加 `hanging` 参数 + 补偿。
  - 调用方透传：`MonitorHitDetector`、`KnobInteractionHandler`（begin/tick/computeCrosshairAngle）、`MonitorGridOverlay`（`monitorHanging` 贯穿 drawGridLines/drawModuleOutline/world）。
  - 不动的：屏幕常量、`MonitorBlockEntity`、NBT、网络、Lua、落地态。

### Step 2 踩坑：pitch 旋转中心错位

- **现象**：初始位置（pitch=0）正确，一调 pitch 后 case 模型与选择框描边错位 2px（选择框旋转正常）。
- **根因**：drop 与 pitch 的**调用顺序反了**——之前 drop 是渲染链最内层（顶点先 drop 后 pitch），case 实际绕模型 **y11** 旋转（比正确铰链 `HINGE_Y=9` 低 2px）；描边是"先 pitch 后 drop"（绕 y9）。pitch=0 纯平移顺序无影响 → "初始对、一调就偏"。
- **修复**：全部统一为**顶点先 pitch（绕模型铰链 y9）后 drop**：
  - `MonitorRenderer`：`applyHangingCaseDrop` 移到 `applyPitch` 之前调用；
  - `MonitorVisual`：caseDrop translate 移到 pitch rotateAround 之前；
  - `MonitorBlock.inverseToModel`：下移补偿移到 yaw 逆之后、pitch 逆之前；`transformPointToLocal`：下移补偿移到 pitch 之后、yaw 之前；
  - `MonitorOutlineRenderer`：本来就是"先 pitch 后 drop"，作为正确基准不动。
- 现在渲染、描边、命中三侧一致：case 绕自身中心（模型铰链 y9，下移后世界 y7）旋转。
