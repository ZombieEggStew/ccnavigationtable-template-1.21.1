## 📝 本次工作记录 / 注意事项

### 改动摘要
- 频道系统抽成通用 `ChannelRegistry<O>`（PeripheralExtender 用），GUI 跳过逻辑抽成 `ChannelScrollHelper`（三个 GUI 共用）。
- Monitor 模块由「全局频道」改为「per-monitor ID」：删除 `MonitorChannelRegistry`，ID 0..9999 在单个 monitor 内唯一，模块与屏幕共用命名空间。
- 屏幕获得独立 `id` + `text`；统一配置菜单（模块/屏幕复用 `MonitorModuleScreen`）。
- 新增 section 框架：`ModuleConfigSection` / `ModuleConfigSections` / `ButtonConfigSection`，模块配置存 `GridState.moduleConfigs`。
- 网络统一为 `ModuleConfigPayload`（一次带 id + text + 各类型专属 config）。

### 需要注意的坑
- `GridState.trySetId` 改 ID 时必须同步 re-key：`modules`、`grid[][]`、`pressedModules`、`knobAngles`、`moduleConfigs`（新增字段时别漏）。
- section 实例由 `ModuleConfigSections` 工厂**每次新建**，不要做成单例（内部持有控件引用）。
- 屏幕(`name == "screen"`)和未注册类型都走 `ModuleConfigSection.Empty`，不进注册表。
- `MonitorBlockEntity` 必须重写 `getUpdatePacket()`（默认返回 null），否则 `sendBlockUpdated` 不会推 BE 数据到客户端。
- 扳手右键模块：交互检测需排除 `holdingWrench`，否则拆卸前会先触发一次按下。
- 模块 ID 命名空间已包含屏幕，`GridState.getOccupiedIds()` 返回二者并集，菜单滚轮跳过时要用它。
