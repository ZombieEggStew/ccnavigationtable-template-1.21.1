## 📋 正式 Monitor 可动化 — 后续实施流程

### 总体目标

将测试 Monitor 已验证的 `facing + offset + yaw + pitch` 变换能力迁移到正式 Monitor，同时保留既有的网格、模块、屏幕、频道、背景、Lua 外设与客户端交互功能。

最终模型层级：

```text
底座（固定，仅 facing）
└── bearing（offset + yaw）
  └── case（offset + yaw + pitch）
    └── 背景、模块、屏幕边框、屏幕文字与矩形
```

正式 Monitor 的模块局部坐标、`GridState`、模块动画和 Lua API 不应因可动化而改变；它们只需继承 case 的外层变换。

### 推荐实施顺序

#### 阶段 1：正式 Monitor 模型拆分

- [ ] 将正式 Monitor 世界渲染拆为 `base`、`bearing`、`case` 三个独立 BakedModel；物品栏继续使用静态 item 模型。
- [ ] 在 `MonitorPreloadedModels` 的两处模型事件中注册并预加载新增模型。
- [ ] 调整正式 Monitor 的静态世界模型，避免完整外壳被方块模型固定渲染后又被 BER 重复渲染。
- [ ] 在 `MonitorRenderer` 中先验证无变换时的 base、bearing、case 组合外观与旧版完全一致。

验收：`pitch=0`、`yaw=0`、`offset=0` 时，正式 Monitor 无模型重叠、无缺面，外观与当前静态版本一致。

#### 阶段 2：正式 Monitor 变换状态与同步

- [ ] 在 `MonitorBlockEntity` 增加 `pitchAngle`、`yawAngle`、`offset` 状态及范围钳制：pitch `-90..90`、yaw `-180..180`、offset `-6..6` 像素。
- [ ] 将三个状态加入 `saveAdditional`、`loadAdditional`、`getUpdateTag` 和 `getUpdatePacket`，由服务端 `sendBlockUpdated` 推送到客户端。
- [ ] 将 `PitchMonitorTransform` 抽为可被测试和正式 Monitor 共用的 `MonitorTransform`；枢轴常量与正反变换只保留一个实现来源。
- [ ] 将测试用的角度 payload 泛化为正式 Monitor 可用的变换 payload，服务端只接受对应 BlockEntity 并调用其 `setAngles`。

验收：修改变换后，其他追踪客户端可见相同状态；退出并重新进入世界后角度和偏移不丢失。

#### 阶段 3：正式 Monitor BER 变换接入

- [ ] `MonitorRenderer` 先应用 facing 并渲染固定 base。
- [ ] 在 offset + yaw 层渲染 bearing。
- [ ] 在 offset + yaw + pitch 层渲染 case、背景、所有模块、屏幕九宫格、按钮标签、旋钮角度文字、屏幕文字和矩形。
- [ ] 保持 `ModuleRenderBehavior` 的模块局部偏移、初始旋转和动画逻辑不变。

验收：底座在所有角度固定；bearing 不跟随 pitch；case 与所有屏幕内容严格跟随 pitch、yaw 和 offset。

#### 阶段 4：正式 Monitor 配置入口

- [ ] 保留 `MonitorMenuScreen` 的频道和背景配置。
- [ ] 推荐新增独立的 `MonitorTransformScreen`，仅提供俯仰、偏航、前后偏移三条滚轮；由正式 Monitor 菜单的图标按钮进入。
- [ ] 关闭变换界面或点击完成时一次性发送变换 payload。

说明：不建议把五条滚轮强塞进现有 `159px` 高菜单；独立页面可以复用测试菜单的已验证布局，也便于以后扩展。

验收：正式 Monitor 菜单可进入变换页；修改、完成、重开菜单时数值一致。

#### 阶段 5：动态屏幕射线与模块交互迁移

- [ ] 正式 Monitor 的屏幕命中改为完整视线射线：世界/plot 坐标减去 `BlockPos` 后，调用 `MonitorTransform.inverseToModel`，再与模型空间屏幕平面求交。
- [ ] 将求交结果转换为网格坐标，替代仅按 facing 反转静态命中点的 `worldHitToGrid` 路径。
- [ ] 迁移模块放置、拆除、按钮按压/释放、Toggle 点击、Knob 拖拽、屏幕区域选择、模块悬浮和屏幕悬浮等所有客户端交互。
- [ ] 继续使用 `SableCompat.toLocalPosition/toLocalDirection`，保证子次元中的世界射线与 BE 的 plot 坐标处于同一坐标系。

验收：在四个 facing、正负 pitch、正负 yaw、正负 offset 下，准心看到的格子与实际可放置/可交互格子一致；Sable 子次元不出现错位。

#### 阶段 6：动态选择框与碰撞体

- [ ] 将测试 Monitor 的自定义描边泛化到正式 Monitor，使选择框跟随 offset、yaw、pitch。
- [ ] 碰撞体保持底座静态，避免动态完整 `VoxelShape` 频繁重建和实体卡位问题。
- [ ] 若正式 Monitor 仍需动态 `getShape`，按离散状态懒缓存，绝不能在每帧或每次视线命中时重建复杂 shape。

验收：选择框与可动 case 一致；实体碰撞仅由底座承担；观察方块时没有因 shape 重算造成的掉帧。

#### 阶段 7：回归与测试方块处理

- [ ] 对静态默认状态运行现有 Monitor 的放置、移除、按钮、Toggle、Knob、屏幕、频道、背景与 Lua API 回归测试。
- [ ] 对可动状态运行四朝向、角度边界、偏移边界和 Sable 子次元测试。
- [ ] 正式 Monitor 稳定前保留测试 Monitor，作为变换、射线和描边的回归基准。
- [ ] 稳定后再决定测试方块是否保留为调试工具或删除；共用的变换/射线逻辑保留。

### 正式 Monitor 可动化的关键约束

- 渲染正向和命中检测逆向必须共用同一 `MonitorTransform`，并保持严格互逆：`facing -> offset -> yaw -> pitch`，检测为相反顺序且旋转取负。
- `PoseStack` 后调用的变换为内层、先作用于顶点，yaw/pitch 顺序不可交换。
- base 绝不能进入 offset/yaw/pitch 层；bearing 不进入 pitch 层；case 内所有视觉内容必须进入 pitch 层。
- 不要改动 `GridState` 或模块局部模型坐标来适配旋转，应由外层 case 变换统一带动。
- 不要继续使用原版静态方块外壳命中点作为动态屏幕交互依据；可动屏幕必须从完整射线求交获得局部坐标。
- 正式 Monitor 原版 `getShape` 无法准确代表连续 yaw/pitch 的完整外壳；动态外壳选择框使用客户端自定义描边，实体碰撞保持静态底座。
- 模型资源需检查 `render_type`：若 case 前脸需要让内嵌 screen 面板透出，应使用 `minecraft:cutout`，避免不透明面遮挡屏幕内容。
- 任何对 `MonitorBlockEntity` 的状态变更都必须保留原有 `GridState` 自定义包同步逻辑，变换状态则通过 BE update tag/packet 同步；两条同步路径职责不同。

## 📝 本次工作记录 / 注意事项

### 测试 Monitor 变换方案（facing + offset + yaw + pitch）
- **模型层级**：底座（固定）→ bearing（偏航支架）→ case（头部，含屏幕/棋盘）。
- **变换顺序**（PoseStack 后调为内层、先作用于顶点）：`facing(方块中心,Y) → offset(前后平移,Z) → yaw(颈部,Y) → pitch(铰链,X)`。
  - facing 作用于整体；offset/yaw 作用于 bearing+case；pitch 只作用于 case。
- **枢轴静态常量（定义在 `PitchMonitorTestBlock`，单位=模型像素，微调只改这里）**：
  - `HINGE_Y=9`、`HINGE_Z=8`（俯仰铰链，case 侧轴承中心）
  - `NECK_X=8`、`NECK_Z=8`（偏航颈部，bearing 水平中心）
  - 铰链与颈部同 z=8，构成单点万向（gimbal），yaw 时铰链不画弧。
- **offset 语义**：正值向前（朝屏幕 -Z），相对 facing 前后平移 case+bearing；单位 1/16 方块（1px）。
- **yaw 语义**：相对 facing（yaw=0 即当前朝向）。
- **命中检测**：世界/plot → 模型空间逆序 `facing逆 → offset逆 → yaw逆 → pitch逆`（正向的逆序、旋转取负、平移取反）。
- **万向锁**：不处理，模组介绍中提示玩家避免 pitch=±90° 相关表现。

### 需要注意的坑
- 测试 monitor 的 `getShape` 不要每帧动态重算（`VoxelShaper.forHorizontal` + 12 切片 `Shapes.or` 很贵，会造成视角对准时掉帧）；已改为按 (facing,pitch) 懒缓存，碰撞 `getCollisionShape` 只用底座。
- **Sable 子次元坐标不一致**：`blockEntity.getBlockPos()` 是 plot（局部）坐标，玩家视线是 world 坐标，必须用 `SableCompat.toLocalPosition/toLocalDirection`（即 `Pose3dc.transformPositionInverse/transformNormalInverse`）把射线投回 plot 再求交，否则悬停高亮错位。Sable 的选择框描边已由 Sable 自己的 mixin 处理，不用额外适配。
- **渲染与检测必须严格互逆**：正向（PoseStack）与逆向（射线求交）的变换顺序、枢轴常量必须一致；集中在 `PitchMonitorTransform` 单一来源，避免各写各的导致镜像/错位。
- **旋转顺序不可交换**：三维旋转不满足交换律，facing/yaw/pitch 顺序不能乱；PoseStack 后调用的 `mulPose` 是内层（先作用于顶点）。
- **单位约定**：枢轴常量存像素（1/16 块），PoseStack 里用 `/16f` 转块；`createPitchedCaseShape` 直接用像素算。
- 测试 monitor 的 `my_monitor_case.json` 没有 `"render_type": "minecraft:cutout"`（静态 monitor 的 `my_monitor.json` 有），case 前脸会不透明、挡住 z=5 的 screen 面板；棋盘画在 z=3.99 前面不受影响。若要 screen 面板透出，需给 case 模型加 cutout。
- `GridState.trySetId` 改 ID 时必须同步 re-key：`modules`、`grid[][]`、`pressedModules`、`knobAngles`、`moduleConfigs`（新增字段时别漏）。
- section 实例由 `ModuleConfigSections` 工厂**每次新建**，不要做成单例（内部持有控件引用）。
- 屏幕(`name == "screen"`)和未注册类型都走 `ModuleConfigSection.Empty`，不进注册表。
- `MonitorBlockEntity` 必须重写 `getUpdatePacket()`（默认返回 null），否则 `sendBlockUpdated` 不会推 BE 数据到客户端。
- 扳手右键模块：交互检测需排除 `holdingWrench`，否则拆卸前会先触发一次按下。
- 模块 ID 命名空间已包含屏幕，`GridState.getOccupiedIds()` 返回二者并集，菜单滚轮跳过时要用它。
- tooltip 显示开关存于模块配置的 `showTooltip`；旧存档无此字段时按开启处理。
