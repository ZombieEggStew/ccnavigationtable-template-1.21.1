## 0. 目标与验收指标

- 复刻"特斯拉 Roadster 倒挂行驶 / 冲坡腾空 / 侧空翻 / 平稳落地"的观感：
  1. 在横向 U 型弯道上**倒挂行驶**（喷嘴吸力吸附）；
  2. 冲出坡口后**腾空侧空翻**（绕机体纵轴 Roll）；
  3. **平稳落地**。
- 用户给定验收指标：
  - 触地竖直速度 **≤ 1.5 m/s**；
  - 落地时 pitch/roll 偏差"不大"即可（未给具体角度）；
  - **允许偏航漂移**；
  - 翻转过程中用户手动关油门，**落地后不需要继续行驶**。
- 载具：Sable 物理体 + CC:Tweaked 电脑（电脑 id = 3）；装有 AIC（同时满足 INS + FMC 门控，故姿态/位置/质量类 API 全部可用）。

## 2. 传感器与执行器语义（源码侧事实）

### 2.1 `ccpe.sensor_system`（`compat/cc/SensorSystemAPI.java`，Lua 方法全部 `mainThread=false` 直读缓存）

| 方法 | 返回 | 门控 |
|---|---|---|
| `getAngles()` | `{pitch, roll, yaw}` 度 | 机体（含约束链）有 ≥1 INS/AIC |
| `getPosition()` | 最后放置的 INS 世界坐标 | 同上 |
| `getBodyPosition()` | 物理体原点世界坐标 | 同上 |
| `getOrientation()` | 四元数 `{x,y,z,w}` | 同上 |
| `getAngularVelocity()` | 机体局部系角速率 rad/s | 同上 |
| `getAngleRates()` | 三轴欧拉角速率 deg/s | 同上 |
| `getVelocity()` | 世界系线速度 m/s（机体原点平移） | 同上 |
| `getPhysicsMass()` / `getPhysicsChainMass()` | kg | 机体有 ≥1 FMC/AIC |
| `getPhysicsGravityForce()` | pN = 质量 × **11** | 同上 |
| `getPhysicsCenterOfMassRel()` / `getPhysicsChainCenterOfMassRel()` | 相对最后放置 FMC 的局部坐标 | 同上 |
| `getAltitude()` / `getPressure()` | 静压孔高度 / 气压 | 机体有静压孔 |
| `getPeripheral(ch)` | 频道 → 外设 | 不门控 |

- 门控不满足时返回 **nil**（脚本必须 `or 0` 兜底）。
- 姿态欧拉角算法 = gimbal_sensor 重力投影（`computeAttitudeDeg`，源码 1903 行）：
  `pitch = atan2(ld.z, -ld.y)`、`roll = atan2(ld.x, -ld.y)`、`yaw = -atan2(n.x, -n.z)`。
  **⚠️ 倒挂时 ld.y>0 会进入奇异保护分支（pitch 被强制为 0）→ 一旦翻滚超过 90° 欧拉角不可用于控制，必须用四元数。**
- 姿态取自 `logicalPose().orientation()`（几何姿态，不是加速度计），**推力再大也不会被污染**。

`TransmissionPeripheralBlockEntity.setTargetSpeed/setServoMode`、`SolidFuelThruster.setPowerNormalized` 均为 `@LuaFunction(mainThread = true)` → 见 §3.2。

### 2.3 喷嘴与角落风扇的符号（实测）

| 器件 | 符号约定 |
|---|---|
| 喷嘴（频道 7/8） | **负转速 = 朝载具下方吸（吸附）**；**正转速 = 朝上方推（刹车）** |
| 角落风扇（二代，2/3/4/5） | **前后极性镜像**：`fl, fr` 负转速 = 向上推；`bl, br` 正转速 = 向上推。实测 `fl=-256, fr=-256, bl=+256, br=+256` 为四扇全部向上 |
| 火箭（10~13） | `power > 0` = 向上推（四台同向，实测四台同时点火不产生任何俯仰/滚转） |

### 2.4 传动方向

用户 `startup.lua` 用 `transmission_back.setTargetSpeed(throttle_value * -256)`，即**旋钮正 = 送负值 = 前进**。`vtel.lua` 里以 `TRANS_SIGN = -1` 编码。初代脚本用的是 `+256`（正旋钮倒车），曾导致"转油门不走车"的误判。

## 3. CC:Tweaked 层面的三个硬约束（踩过的坑）

### 3.1 外设方法**没有隐式 self**

```lua
-- 正确（startup.lua 的写法）
p.setTargetSpeed(128)
-- 错误：把外设表自身当成第一个参数喂进去 → 每次都报错
p.setTargetSpeed(p, 128)
```

**坑**：包一层 `pcall` 会把这个错误静默吞掉，表现为"程序不报错但什么都没发生"。`vtel.try` 现在会记录 `errorCount / lastError`，测试结束时打印。

### 3.2 `mainThread` 写：**每个 `parallel` 块吃 1 个 tick，块内条数不限**（旧结论「一 tick 最多 6 个」已作废 → §22）

Lua 线程调用 mainThread 方法会阻塞等待服务端线程执行。用 `parallel.waitForAll` 并发发出可让多个调用共享同一 tick。

| 写法（每周期） | 实测 dt | 频率 | 同步点数（2026-11 新模型） |
|---|---|---|---|
| `read` + `sleep(0)`（无写） | 0.05 s | 20 Hz | 1（sleep） |
| `read` + **4 个顺序写** + `sleep(0)` | **0.25 s** | **4 Hz** | 4 + 1 |
| `read` + `apply`(6 写，并发) + `sleep(0)` | 0.10 s | 10 Hz | 1 + 1 |
| `read` + `apply`(6 写，并发) | **0.05 s** | **20 Hz** | 1 |
| `read` + `apply`(2 喷嘴写) | 0.05 s | 20 Hz | 1 |
| `read` + `rocket`(4 写，并发) + `sleep(0)` | 0.10 s | 10 Hz | 1 + 1 |
| `read` + `rocket`(4 写，并发) | **0.05 s** | **20 Hz** | 1 |
| `read` + `apply`(6) + `rocket`(4) = **10 写** | **0.10 s** | **10 Hz** ❌ | **2（两个块）** |

**结论（2026-11 修正，证据见 §22）**：
- **`dt = 0.05 s × (本周期 `parallel` 块数 + `sleep` 次数)`。块内写多少条都不额外收费** ——
  10 条挤在一个块里实测仍是 **20 Hz**（§22.1 反证）。
- 上表最后一行掉到 10 Hz 的真因是 `apply` 和 `rocket` 是**两个独立的 parallel 块**，**不是**「写了 10 条」。
- ⇒ **每周期只能有一个写块**。新增执行器（四驱的 2 组传动等）并进同一个块 = **零频率代价**。
- **`apply` 本身已经同步到 tick，后面再加 `sleep(0)` 会白等一帧**（0.05 → 0.10）。控制环里**不要**加 `sleep(0)`。
- **顺序（不并发）写每条各吃 1 tick**，这是唯一真正昂贵的写法 —— 批量写必须包在 `parallel` 里。
- 有效执行延迟 ≈ 1~2 tick（50~100 ms），控制器必须做延迟补偿/外推。

### 3.3 其他

- `MonitorPeripheral.getModule(id)` 也是 `mainThread=true`，**只能在启动时取一次**，不要放循环里。
- 踏板 `getPedalDifference()`（−1..1，脚本里再 /2 得 −1..1 的转向量）与旋钮 `getAbsolutePercent()`（0..1，无物理限位时可能 >1 或为负）都是 `mainThread=false`，可高频读。
- 旋钮读数取 **绝对角度/最大旋转角**，所以旋钮没归零时程序一起动就会读到一个非零值。

### 5.4 欧拉角与角速度的轴映射（实测校准）

用 drop1 里恒定的离台俯仰率反解：

```
d(pitch)/dt = −23.5 °/s = −0.41 rad/s，而 CSV 中 ω_z = −0.41
滚转测试中 ω_x 增长 ↔ Euler roll 增长
⇒ ω_x = 滚转率，ω_z = 俯仰率，ω_y = 偏航率
```

**这与"pitch 绕局部 X"的源码注释不一致**（按注释应 ω_x 是俯仰）。**结论：控制器不要直接信任 ω 的分量轴，改为对四元数自行差分求机体角速度**（噪声底 0.0056~0.016 rad/s，足够干净）。

| 实验 | 力矩 | 实测 α | 反解 I_roll |
|---|---|---|---|
| 二代角落风扇滚转（双向，横向力臂 r=2 m，F=57.6 pN/扇） | τ = 4·r·F = **461 N·m** | 2.8 | **165 kg·m²** |
| 三代火箭滚转（单向，r=2 m，F=197 pN/台） | τ = 2·r·F = **788 N·m** | 5.0 | **158 kg·m²** |

- 两组反解出同一惯量（差 4%），且力矩比 788/461 = 1.71 与 α 比 5.0/2.8 = 1.79 吻合。
- **⇒ τ ∝ r 严格成立，把推力器外移一格 = 力矩 ×1.5（惯量几乎不变）。**
- **⇒ 这台车的转动惯量确实约 160 kg·m²**（回转半径 ≈2 m，质量分布极靠外）。这解释了"转速慢但惯性大"的手感。

### 6.2 落地：**可行，且优于验收指标** ✅

- 喷嘴满推力可在 **h≈2.5 m 处精确悬停**，残速稳定在 −0.5~−1.1 m/s（< 1.5 m/s 要求）。
- 可在 1.4 m 内吃掉 8.2 m/s 的下落速度。
- 火箭（1.78 W、任意高度有效、无距离依赖）可以承担"高位大速度刹车"。
- **前置条件**：进入喷嘴作用区的 h≈6 m 时 |vy| ≤ ~10 m/s，且姿态偏差 ≤ ~20°（喷嘴推力沿机体轴，姿态歪了就变成横向推力）。

### 6.3 侧空翻：**当前差一步** ⚠️

- 可落地翻滚需要「加速 + 减速」，同一 α 下耗时是只加速的 1.41 倍：
  - 180° @ α=2.8（角落风扇）→ 2.1 s；@ α=5.0（火箭）→ 1.59 s
  - 360° @ α=5.0 → 2.25 s
- 可用高度：出弯 y=100，地面 65.6 → **34.4 m**，其中最后约 6 m 必须留给喷嘴。
- 预算要求：**翻滚 ≤1.4 s ⇒ 180° 需 α ≥ 6.4 rad/s²；360° 需 α ≥ 12.8 rad/s²。**

| 方案 | α | 180° 耗时 | 结论 |
|---|---|---|---|
| 火箭 r=2（现状） | 5.0 | 1.59 s | 略不足 |
| **火箭外移到 r=3** | **≈7.4** | **1.30 s** | ✅ 达标 |
| 再加 2 台火箭（每侧 3 台） | ≈7.4 | 1.30 s | ✅ 但写预算超限（7 个）❌ |

### 6.5 其他已验证结论

- 二代角落风扇的**前后镜像极性表正确**：`mix(256,0,0)` 让整车均匀上升且**俯仰率全程无变化**。

### 21.5 关于「后驱爬坡动力不够」—— 改结构之前先看这个

```
θ=30°、吸力 45%（895 pN）：N = 580x0.87 + 895 = 1400 pN  ≈ 最小值的 2.8 倍
```

- **爬坡时把吸力开满**（但别超过 60%，会弹射）=> 可用的牵引力上限能翻 2~3 倍。

## 22. 前提修正（2026-11）：写预算的真实规则 + 结构改为四驱

### 22.1 更正：没有「一 tick 最多 6 个 mainThread 写」这回事

**反证（用户既有程序，长期飞行验证过）**：
`run/saves/trainer aircraft v2/computercraft/computer/0/startup.lua`（飞控，372 行）
循环末尾只有一个 `parallel.waitForAll` 块（第 346~365 行），块内全是 mainThread 写：

| 频率 | 条目 |
|---|---|
| 每 tick | `engine.setThrottle`、`servo_r.setTargetAngle`、`servo_l.setTargetAngle`、`screen_1.drawCells`、`screen_2.drawCells`、`ss.setAllLights`、`redstone.setOutput` = **7 条** |
| 每 10 tick 再加 | `engine.setMixture`、`engine.setCooling` = **9 条** |
| 摇杆接管瞬间再加 | `setToggleState` = **10 条** |

- 该程序自带速率打印（`(os.clock() - clock)/100`），用户实测**一直输出 0.05**（= 20 Hz）。
- 全程**没有 `sleep(0)`**；写全部并发在一个块里，**10 条也不掉频**。

**正确模型**

> `dt = 0.05 s × (本周期内 `parallel.waitForAll` 块数 + `sleep` 次数)`
> **块内条目数不影响 dt**；顺序（不并发）发出的每条写各吃 1 tick。

用这个模型重算 §3.2 的 6 组实测，**全部吻合**（当初的数据没错，只是被误读）：

| 写法 | 实测 dt | 同步点数 |
|---|---|---|
| `sleep(0)`（无写） | 0.05 | 1（sleep） |
| 4 个顺序写 + `sleep(0)` | 0.25 | 4 + 1 |
| `apply`(6) + `sleep(0)` | 0.10 | 1 + 1 |
| `apply`(6) | 0.05 | 1 |
| `apply`(2) | 0.05 | 1 |
| `apply`(6) + `rocket`(4) | 0.10 | **2（两个块）** ← 当初被误读成「10 写超限」 |

- 「10 写掉到 10 Hz」的真因是 `apply` 和 `rocket` 是**两个独立的 parallel 块**，不是写了 10 条。
- 当时 `apply` 恰好 6 条，数字撞上 6，于是总结出了并不存在的「6 个上限」。
- ⇒ 新增执行器（尤其四驱的 2 组传动）**不产生频率代价**，只要并进同一个写块。
- 仍然成立的两条：**`sleep(0)` 会白等一帧**；**顺序写每条 1 tick**。

### 22.3 接触探测器（新，2026-11）

Java 事实（`SensorSystemAPI.java:1766-1770`、`ShortRangeLinkerBlockEntity.java:371-374`）：

```java
@LuaFunction                       // 没有 mainThread=true ⇒ 直读缓存，零 tick 成本，可每周期读
public final int getRedstoneInput(int channel) {
    ShortRangeLinkerBlockEntity linker = ShortRangeLinkerRegistry.getLinker(chainUuids, channel);

}
public int getRedstoneInput() { return this.level.getBestNeighborSignal(this.worldPosition); }
```

| 事实 | 含义 |
|---|---|
| `mainThread=false` | **读探测器不占写块、不掉频**，可放在控制环里每周期读 |

| `setRedstoneOutput(ch, 0~15)` | 反向也能**由 Lua 输出红石**（mainThread=true，要算进写块） |

### 22.6 探测器真相：`simulated:optical_sensor` 是 CC 外设，不是红石源

源码（`references/Simulated-Project-main`）：

| 位置 | 事实 |
|---|---|
| `compat/computercraft/peripherals/OpticalSensorPeripheral.java` | 外设方法 `hasHit()` / `getDistance()` / `getBlock()` / `getRange()`，全部 `@LuaFunction`（**mainThread=false，免费轮询**）；`setRange()` 才是 mainThread=true |
| `.../optical_sensor/OpticalSensorBlock.java:87-106` | `isSignalSource = state.getValue(POWERED)`；`getSignal = round((range − distance) × 15 / range)`，且 **`side != FACING.getOpposite()`** 才输出 |

⇒ 红石读数**不是布尔**，三种情况都是 0：

1. 没有命中（`POWERED` 为假）⇒ 0；
2. 命中了但距离接近射程上限 ⇒ 四舍五入到 **0**；

**正确用法**：`ss.getPeripheral(15/16)`（`mainThread=true`，**只能启动时取一次并缓存**）返回的是
**链接器所附着方块的外设** —— 直接对光学传感器调 `hasHit()` / `getDistance()`。
`vtel.prox()` / `vtel.proxRead()` 已实现，`tests prox [秒]` 用来验证。

- 附加收获：`getDistance()` 是真测距 ⇒ 天然高度计，FLARE 段比静压孔更直接。
- 踩坑：`peripheral.getType(<wrapped peripheral>)` 在此 CC 版本返回 nil，所以 `tests id` 里的 `type=?` **不代表设备缺失**。

### 22.12 autopilot v2 首飞踩到的两个 bug（`log/auto_hover.csv` 实证）

**bug 1：俯仰差动打错了执行器（结构性）**

  `base ≤ 256-(|r|+|p|)` 保证差动余量；竖直组回归纯集合。

**bug 2：姿态阻尼符号写反（致命）**

- 姿态误差的导数 `ė = -ω`（机体往正方向转，需要转的量就变小），所以 `u = KP·e + KD·ė = KP·e - KD·ω`。

| 3.15 | 8.5° | -0.15 | 0.44 | **+78** | 越转越帮 |
| 3.30 | 13.2° | -0.23 | 0.60 | +70 | P 项开始压过 D 项 |

  从 `FLast=0` 起步，要 2.8 s 才能给到 1400 pN，而车只有 1.9 s 就落地 ⇒ 全程基本自由落体，FLARE 只剩 0.35 s。
- 修法：**限速只在「探测器踩着面 or h<2.5 m」时生效**（它本来只是为了防地面弹射），空中不限速。
- 顺带补上**倾斜补偿** `F/clamp(cosVert, COS_MIN)`（旧代码只在倾角处断推力，不补偿）。

**第三项：`autopilot stickflip 180`（日志落在 `auto_stick.csv`，因为两者共用 mode）—— 不稳定 ❌**

| t | 事件 | h | vy | tilt |
|---|---|---|---|---|
| 0 | STICK（倒扣吸住） | 51.36 | 0.00 | 175° |
| 5.05 | → SETTLE | 52.30 | −3.94 | 180° |
| 5.90 | → FLIP | 44.97 | −12.69 | 124° |
| 7.80 | → RECOVER | **3.57** | **−29.93** | 88° |
| 11.80 | → BRAKE | 2.01 | +1.54 | 124° |

两个叠加的 bug：
1. **SETTLE 只给 50% 推力 + 轻阻尼** ⇒ 0.85 s 掉 7.3 m、`vy` 已经 −3.9 才开翻。
2. **FLIP 段 `nf=nb=0`（纯自由落体）** ⇒ 1.9 s 掉 42 m、`vy` 冲到 **−29.9**，翻滚结束时只剩 3.57 m，必然砸。

修法：
- SETTLE 改成**真·吊住**：`F = m(G − 1.5·vy)/cos`，上限 97% 满载；
- FLIP 期间**把「吊住」交给竖直组、四角只做滚转差动**（`allocate(F, rCmd, 0)` 天然优先给竖直组）；
  机体侧倾 >63°（`cos<0.45`）时不出推力，再往后推力方向接近水平只会横向乱推；
- FLIP 退出增加 `s.c.any`（碰到东西就收工）。

**翻滚高度预算（修正后）**：180° 约 1.18 s，其中中间 0.4~0.6 s 只能部分吊住 ⇒ 实际掉高估计 **5~10 m**（旧版 42 m）。
释放高度按 **≥30 m** 准备就够，不必再按 45 m。

### 22.14 第二轮实测：落地「悬在半空」+ 空翻「疯狂旋转」

**落地悬停：`aFF` 前馈的门控写反了**

- `auto_drop`：FLARE 段一路降到 **h=1.33 m 后卡住不动**（`vy=0.00`、`nozUp=176`、`Fcmd=645` 持续 8 s），
  用户最后手动把车按到地上。
- 根因：`aFF = (s.vy > vyRef) and A_REF or 0`。车已经比剖面慢（`vy=0 > vyRef=-1.46`）时仍然加 +8 前馈，
  把本该 −8.8 的误差修正抵消成 −0.8 ⇒ 推力≈重量 ⇒ 空中悬停。
- 修法：**只在沿剖面下坠（`vy <= vyRef`）且 `h > 2` 时加前馈**。

**空翻疯狂旋转：`rCmd` 漏了 `ROLL_SIGN`**

| t | theta | wz | rCmd |
|---|---|---|---|
| 5.10 | −3° | −0.84 | +256 |
| 5.50 | −67° | −4.02 | +256 |
| 6.10 | −301° | −9.80 | +256 |
| 6.90 | **−933°** | **−17.30** | +256 |

- `rollA` 实测：**`rCmd>0` 产生的是「负」ω_z**。姿态 PD 里用 `ROLL_SIGN=-1` 就是为了这个，
  但 FLIP 段我直接写了 `rCmd = 256*aCmd/ALPHA`，漏掉了符号 ⇒ 想刹车时实际在**继续加速**。
- 修法：`rCmd = ROLL_SIGN * 256 * aCmd / ALPHA_ROLL`。

**SETTLE 必须缩短**

- 倒扣（`cosVert ≈ -1`）时集合推力无法吊住，SETTLE 期间等于自由落体：实测 0.85 s 掉 7.2 m、
  进入 FLIP 时 `vy` 已经 −12.4。
- 修法：`tau > 1.0` 或 `(tau > 0.25 且 |wz| < 0.35)` 就开翻，不再等 2.5 s。

**新增：所有 `print` 镜像到 `/log/status_<mode>.txt`**

- CC 终端不能复制，出问题只能靠文件。程序启动即覆盖写，每次 print 立即 flush。
- 对应关系：`autopilot` → `status_drop.txt`、`hover` → `status_hover.txt`、
  `stick`/`stickflip` → `status_stick.txt`、`flip` → `status_flip.txt`。

### 22.16 「上坡途中程序自动退出」——吸附相关判断缺门闩

`status_stick.txt` 实录（从地面启动 stickflip、风扇旋钮一直 0、用油门沿坡道开上去）：

```
h=-0.00 m
!! STICK：机体正立 + 下方有面 —— 这是地面/赛道上面，不是吸附场景。
!! |vy|=6.09 > 6.0 during STICK -> abort suction
>>> TOUCH  h=1.36 vy=3.56
=== finished: landed ===
```

三个判断都被「没在吸的普通驾驶」误触发：

1. **正立守卫**：只要正立+有面就报警，不管有没有在吸；
2. **`|vy|>6` 急停**：上坡冲出去正常腾空 vy=6.09 被当成弹射故障；
3. **释放逻辑**：旋钮一直是 0 ⇒ 0.5 s 后就会判定「释放」⇒ 一启动就翻。

**修法：加 `stickArmed` 门闩** ——

```lua
if fan > 0.15 then stickArmed = true end                      -- 吸过才算上膛
local suctionOn = stickArmed and (stickFrac > 0.10 or fan > 0.10)
  正立守卫  -> 只在 suctionOn 时生效
  |vy|>6 急停 -> 只在 suctionOn 时生效
  旋钮归零释放 -> 只在 stickArmed 之后才认
```

⇒ **正确的上坡流程**：启动 `stickflip 180` → 风扇旋钮保持 0，用油门沿坡道开上去（程序只跟油门、绝不释放）→
机体倒扣贴住赛道后拧风扇旋钮 ~0.4 吸附 → 想释放再拧回 0 保持 0.5 s。

⚠️ 历史对照：§16.3 曾经因为「`armed` 要求旋钮先 >0.3 才上膛」而永远不释放，被删掉；
这次是**同一个门闩的另一种需求**（上坡阶段不许释放），所以以 `stickArmed` 的形式回来了 —— 两者并不矛盾。

### 22.17 ★最终需求定稿（2026-10-26）：吸着爬坡 → 冲出赛道 → 自动滚转 180° → 平稳落地

**用户明确的四步流程**

1. 爬坡过程中**吸力全程开着**（不能只靠离心力贴住躺倒的 U 轨，必须靠吸力附着）；
2. 以一定速度**冲出赛道口**；
3. **滚转 180°**（倒扣 → 正立）；
4. **平稳着陆**。

⇒ 关键变化：**触发翻滚的不是「手动把旋钮拧回 0」，而是「冲出赛道」这个物理事件**。

**实现（`autopilot track` 或 `autopilot stickflip 180`）**

```lua
-- 吸着的时候两个探测器同时失锁 = 冲出赛道口 => 0.10 s 去抖 => 立刻 SETTLE -> FLIP
if suctionOn and s.c.air then
    exitStreak = exitStreak + dt
    if exitStreak > 0.10 then
        print(">>> TRACK EXIT  h=... vy=... tilt=...")
        stickFrac = 0; enter(P_SETTLE)        -- 不再等旋钮
    end
end
```

- 手动拧旋钮回 0 仍然可用（备用手段，`stickArmed` 门闩后才认）；
- `SETTLE_T 0.25 / SETTLE_MAX 0.80`：冲出赛道时车已经在飞，只做很短的角速度整顿就开翻；
- 新增别名 `autopilot track`（等价 `stickflip 180`），日志落在 `status_stick.txt`。

**同时必须改的两处守卫（否则上坡阶段会被误杀）**

| 守卫 | 旧行为 | 新行为 |
|---|---|---|
| 正立弹射保护 | 「正立 + 有面 + 在吸」就报警，2 s 后**退出程序** | 追加「水平速度 < 2 m/s（停着）」才判定，且**只把吸力钳到 30%**、不退出 |
| `|vy|>6` 急停 | 只要在吸就判故障 | 同样要求「水平速度 < 2 m/s」；高速爬坡/冲出去的 vy 属正常 |

- 理由：沿 U 轨爬坡时车是「正立或侧倾 + 高速前进 + 在吸」，和「停在地面上被吸住弹射」在姿态上无法区分，
  只能靠**水平速度**区分。

**操作流程（最终版）**

```
Ctrl+T 停 startup
autopilot track            (或 autopilot stickflip 180)
风扇旋钮 -> ~0.4，保持不动（吸力全程开着）
用油门旋钮沿 U 轨冲上去（程序只跟油门和吸力，不干预）
冲出赛道口 => 自动 TRACK EXIT => FLIP 180 => 回正 => 落地
```

⚠️ 高度预算：180° 空翻实测掉 **16 m**（§22.15），所以赛道口离地面最好 ≥25 m，
且冲出时带向上的速度更从容（倒扣吸力本身在脱离瞬间推的是世界「上」方向）。

### 22.18 ⚠️ 出口判据用错标志：爬到竖直段就提前翻滚（2026-10-26 实测）

**现象**：探测器量程提到 3 m 后，车在竖直爬坡段就触发 `TRACK EXIT` 开始翻滚。

**根因**：我用的判据是 `contact.air`，而 `air` 的定义是「离面超过 `CONTACT=1.95 m`」，
也就是**车离赛道 0.2 m 就算**。爬坡时车被颠 0.2~0.3 m 是家常便饭 ⇒ 立刻误判。
提高量程到 3 m **并不改善**这件事（`CONTACT` 阈值仍是 1.95 m）。

**正确判据：`contact.lost`** —— 两个探测器 `hasHit()` **都为 false**，即「3 m 内什么都没照到」。
颠簸时车还在赛道附近 3 m 内，探测器照样能照到 ⇒ 不会误判。

**三重判据（含兜底）**

| 条件 | 含义 |
|---|---|
| `.lost` 持续 **0.25 s** | 真的离开赛道 |
| `.lost` 持续 **0.10 s** 且倾角 **>140°** | 已经翻过 U 轨顶部、彻底倒扣 |
| `.air` 持续 **0.5 s** 且倾角 **>120°** | 兜底：出口附近若还有别的结构（U 轨另一臂）使 `.lost` 永不成立 |

- `contact.lost` 与量程数值无关（只看 `hasHit`），以后量程 2/3/5 怎么改都不用动判据。
- 手动把风扇旋钮拧回 0（`stickArmed` 之后）仍然是备用释放手段。
- 若仍有竖直段误触发，下一步手段：把 FLIP 入口再加一道「倾角必须 >100°」的硬门槛。

### 22.19 「竖直段提前翻滚」二次定位：不是出口判据，是弹射判定误杀

`status_stick.txt` 实录（探测器量程 3）：

```
!! |vy|=17.40 > 6.0 且几乎没前进 => 判定被弹射，切断吸力
>>> TOUCH  h=1.27 vy=-3.96
=== finished: landed ===
```

- `.lost` 判据这次**没有**误触发（竖直段没有 `TRACK EXIT`）⇒ §22.18 的修改是对的。
- 真正误杀的是**弹射保护**：它用「`|vy| > 6` 且水平速度 < 2」判断「停着被弹射」，
  但**竖直爬坡时速度几乎全是垂直的**（vy=17.4，vx/vz≈0）⇒ 水平速度天然很小 ⇒ 被当成弹射。

**修法：弹射判据改用竖直加速度，而不是速度大小**

```lua
local vyRate = (s.vy - vyPrev) / dt
if suctionOn and math.abs(vyRate) > 35 and math.abs(s.vy) > 4 then  -- 弹射：|a| 40~90 m/s2
    切断吸力
elseif suctionOn and math.abs(s.vy) > 28 then                        -- 兜底硬上限
    切断吸力
```

| 场景 | 速度特征 | 加速度特征 | 判据是否命中 |
|---|---|---|---|
| 竖直爬坡 | vy 可以到 17+ | 个位数 m/s² | ❌ 不命中（正确） |
| 坑 #8 弹射 | vy 0.3~0.6 s 内冲到 +27 | **40~90 m/s²** | ✅ 命中 |

- 新增 `CFG.ABORT_ACC = 35 m/s²`；旧的 `ABORT_VY=6` 退役。
- **教训**：「水平速度小」不等于「没在动」—— 在竖直面上它就是大的。凡是判「是否在运动」
  的地方都要用**速度矢量模长**，而不是水平分量。

### 22.20 第三次误杀：撞上坡道 = 加速度脉冲，和弹射无法区分

`status_stick.txt` 实录：

```
!! 竖直加速度 64 m/s2 爆表（vy=4.2）=> 判定被弹射，切断吸力
>>> TOUCH  h=1.39 vy=3.66
=== finished: landed ===
```

- 车**以一定速度撞上坡道**时，`vy` 从约 −2 弹到 +4.2，`dv/dt` 实测 **64 m/s²** ——
  和坑 #8 的弹射（40~90 m/s²）**在加速度上完全重合**，单靠加速度无法区分。
- 唯一可靠的附加特征是**吸力大小**：实测 46% 稳吸、81% 才弹射。

**最终判据**

```lua
if suctionOn and stickFrac > 0.50 and |vyRate| > 35 and |vy| > 4 then  切断吸力   -- 只在大吸力下才认
elseif suctionOn and |vy| > 28 then                                    切断吸力   -- 绝对上限兜底
```

- 用户任务用 40% 吸力 ⇒ 这两个判据**永远不会误触**（撞坡、腾空、爬坡全都不管）。
- 于是 STICK 段在任务里唯一可能的退出方式就是：**出赛道（`.lost`）/ 手动拧旋钮回 0**。
- 这三次误杀的共同教训：**在运动中的载具上，任何「异常」判据都必须先排除“正常的剧烈机动”**。
  最稳的做法是让判据只在「任务不期望机动」的状态下生效（例如大吸力、静止、正立）。

### 22.21 「翻滚转得很怪」：FLIP 目标角写死 180° + SETTLE 抢跑

**实测时间线（`auto_stick.csv`，出赛道 h=66.3 / vy=+8.6 / tilt=156°）**

| t | 阶段 | tilt | wz | 说明 |
|---|---|---|---|---|
| 7.95 | SETTLE 开始 | 156° | 0.00 | 出赛道时还在上升（vy=+8.6，是 60% 吸力顶上去的） |
| 8.75 | FLIP 开始 | **101°** | 2.34 | **SETTLE 期间姿态环已经把车从 156° 滚到 101°** |
| 9.20 | FLIP 中 | 7° | 4.9 | 已经路过正立，但目标写死 180° ⇒ 继续滚 |
| 9.80 | FLIP 结束 | **103°** | 0.8 | 滚了 195°，却**又躺回去了** |
| 9.85~11.85 | RECOVER | 106 → 9° | — | 花了 **1.95 s** 才真正回正，掉高 30 m |

**两个错误叠加**

1. **FLIP 目标角写死 180°**：可是 SETTLE 期间姿态环已经先滚掉 55°，
   再从 101° 硬滚 180° ⇒ 结束时 tilt 又回到 103°，等于白转一圈还多转 90°。
2. **SETTLE 在抢跑**：它跑的是完整姿态 PD，会把车朝正立滚 —— 把翻滚动作吃掉了一半，
   于是整条动作被拆成「PD 滚一段 + 匀加速滚一段」，看起来一顿一顿的。

**修法**

| 改动 | 内容 |
|---|---|
| FLIP 目标角 | `thetaTarget = |eRoll|`（当前姿态绕机体 Z 真正还需要滚多少），只有 <20° 才退回任务给定角度 |
| `flipDir` | `sign(eRoll)`（哪边能减小误差就往哪边滚） |
| SETTLE 的滚转 | 改成**纯阻尼** `rCmd = ROLL_SIGN·256·(−KD·wz)/α`，**不再朝正立滚** ⇒ 完整一圈留给 FLIP |

- 现在的 `>>> FLIP start` 会打印：`need XX deg (tilt was YY deg, ePitch ZZ deg)`，直接看出差多少。
- 残余俯仰误差由 RECOVER 收尾（滚转单独修不了俯仰）。

**这次仍然暴露的一个操作问题**：吸力 60% 在坡道/倒扣段都偏大，日志里连续出现 5 次
`!! 竖直加速度 ... 吸力钳到 30%`。建议 **45%**（`cornerUp ≈ −115`），日志每秒会打印实际值。

**仍未验证**：`auto_drop.csv` 只跑 2.2 s 就 phase 0→4→6（地面护栏可能过敏感，已收紧到 h<2.5 m 才生效）；
`auto_flip.csv` 卡 SETTLE 7 s、卡 FLIP 到落地（已加超时，待复测）。

### 22.23 「越接近出口越早翻滚」：FLIP 一进去就被 `c.any` 踢出来

- 修法：`landed = (两只都接触) and h < 6` 才算真落地。
- 顺带：出赛道去抖做成可调 `CFG.EXIT_HOLD`（`autopilot track 0.4` 覆盖），`TRACK EXIT` 打印 `lost=X.XX s`。

### 22.24 ✅ 翻滚链路稳定 + 触地 −2.07（软启动限速误伤最后 2.5 m）

- theta 连续三轮 −186 / −188 / −185，过冲稳定 5~6°；翻转段掉高 0.14 m。
- 触地 −2.07 超标：`needRamp = (s.c and s.c.any) or s.h < 2.5` 把**落地最后 2.5 m 的补救推力也限速了**。
  改成 `needRamp = (s.c and s.c.any)`；同时剖面加余量 `A_REF 8→9`、`H_SOFT 1.2→1.5`、`VY_TOUCH 1.0→0.9`。

### 22.25 触地修好（−0.44），但 `|eRoll|` 目标把侧翻缩成 26°

```
>>> FLIP start: need 22 deg (tilt was 153 deg, ePitch -152 deg)
>>> FLIP done: theta=-26 deg ... RECOVERED 9.8 deg after 1.40 s
>>> TOUCH  vy=-0.44          ← 落地修复生效
```

- `thetaTarget=|eRoll|` 在俯仰为主的出口姿态下只剩 22° ⇒ 侧翻几乎没做。
- 改回**固定 180°**，并**边翻边修俯仰**（tilt<90° 后用四角俯仰差动把残留俯仰一起收）。

### 22.26 侧向喷口对「滚转更干净」无用（力矩分析）

`τ = r × F`，取 X=俯仰轴、Y=上、Z=滚转轴：

```
τ_x =  0
τ_y =  r_z · F_x      -- 偏航：需要【前后】位置差
τ_z = -r_y · F_x      -- 滚转：需要【上下】高度差
```

- 四角**同一高度**的左右喷口 ⇒ 滚转力矩恒为 0（左右成对抵消）。
- 它们只能给：**偏航**（前两角同向、后两角反向）+ **横向平移**（四角同向）。
- 而「半滚半俯」的根因是**出口姿态本身是俯仰倒扣**，不是偏航漂移、也不是滚转权限不足
  （滚转 α=9.0 是最强轴，俯仰只有 3.11）⇒ **装侧推不改善观感**。

### 22.27 翻滚过冲 32° + 触地 −29.59（后者实际是燃料耗尽，见 22.28 更正）

- 过冲根因：§22.26 的「边翻边修俯仰」把 `pCmdF` 送进 `allocate()`，旧分配器在 `|r|+|p|>256` 时**等比缩**，
  把滚转刹车权限压到 ~72% ⇒ 过冲 6°→32°。修法：**差动预算滚转优先**，俯仰限幅 100→60。
- 触地 −29.59 时：`cmd noz=256`、**`act nf=256`（回读一致）**、实际竖直加速度只有 −8.4 ⇒ 只剩 ~9% 推力。
  质量 63.25 kg 正常、限速未生效、姿态 tilt≈1° ⇒ 排除软件侧全部原因。

### 22.28 真凶：蒸汽引擎燃料耗尽（⚠️ 更正）

> **不是温度问题**。这台车装的是**蒸汽引擎、温度锁定**，`getTemperature` 只是读数。
> **真正的限制是燃料**：长时间满推力把燃料烧干 ⇒ 蒸汽引擎掉转速 ⇒ **全部推进器瞬间失推力** ⇒ 自由落体。
> 这也解释了「命令 256、回读 256、加速度只有 −8.4」——回路/外设/推力模型全部正常，是**没有工质**。

- 对应改动：保留温度闭环（对蒸汽引擎无效但无害、同写块零额外 tick）；**新增 `getFluidTanks` 燃料监控**，
  `[eng]` 行每次打印 `fuel=xx%`，低于 25% 在 `status_*.txt` 告警。
- **操作结论**：任务前先确认燃料充足；燃料不足时宁可缩短/降低动作，不要硬跑满推力。

**本轮最好成绩回顾**：`TRACK EXIT h=65.45 vy=6.66 tilt=159` → `FLIP theta=-184`（过冲 4°）→
`RECOVERED 11.5°/0.90 s` → `TOUCH vy=−0.34`（历史最佳）。

### 23.5 autopilot v2 结构

| 模式 | 流程 |
|---|---|
| `autopilot`（drop） | WAIT 手动 → 探测器判腾空 → BRAKE → FLARE → TOUCH |
| `autopilot hover [h]` | 位置环 → 速度目标（与落地剖面分开） |
| `autopilot stick` | 只管吸力+开车；旋钮归零 0.5 s 释放 → BRAKE |
| **`autopilot track`**（= `stickflip 180`） | **STICK → TRACK EXIT（探测器失锁）→ SETTLE → FLIP 180 → RECOVER → BRAKE → FLARE → TOUCH** |
| `autopilot flip 180\|360` | 从高台正着开出 → 翻滚 → 落地 |

**阶段枚举**：`0 WAIT / 1 SETTLE / 2 FLIP / 3 RECOVER / 4 BRAKE / 5 FLARE / 6 TOUCH / 7 STICK / 8 HOVER / 9 ABORT`

**每周期固定一个 `vtel.commit(cmd, drive, {cool=…})`** ⇒ 20 Hz；全程无 `sleep`。

### 23.6 操作流程（最终版）

```
Ctrl+T 停 startup
autopilot track          （可选：autopilot track 0.4 加长出赛道去抖）
风扇旋钮 → ~0.45~0.50，保持不动（吸力全程在）
油门旋钮沿 U 轨冲上去
  → 程序只跟油门和吸力，不报警、不退出、不干预爬坡
冲出赛道口 → >>> TRACK EXIT → >>> FLIP 180 → 回正 → 落地
```

**输出文件**：`/log/status_<mode>.txt`（所有 print 镜像）+ `/log/auto_<mode>.csv`（39~41 列）。

### 23.7 判据设计四原则（三轮误杀换来的）

1. 只用**物理必然性**做判据（`hasHit`、姿态），不用「速度大小」这种和机动混在一起的量；
2. 判据生效前先限定**状态窗口**（在吸 / 大吸力 / 停止 / 倒扣），把正常机动排除在外；
3. 判据的反应只能是**退化控制量**（钳吸力、切推力），**绝不能是退出程序**；
4. 任何「保护」都要先问：**它会不会把任务本身的能力削掉？**

### 23.8 本轮踩过的坑（按代价排序，全部实测）

| # | 坑 | 教训 |
|---|---|---|
| 1 | 「一 tick 最多 6 个 mainThread 写」是**错的** | 真规则：**块数 = tick 数**，块内条数不限（10 条 = 20 Hz） |
| 2 | 俯仰差动打进竖直组 | 悬停集合已把它顶满 ⇒ 俯仰权限≈0 ⇒ 翻滚。**差动要打在有余量的执行器上** |
| 3 | 姿态阻尼写成 `+KD·ω` | `ė=−ω` ⇒ 必须 `−KD·ω`；否则正反馈，越转越帮 |
| 4 | 俯仰/滚转差动预算等比缩 | 加了俯仰修正就把滚转刹车权限削掉 ⇒ 过冲 6°→32°。**滚转优先** |
| 5 | 软启动推力限速用到空中 | 刹车/落地最后 2.5 m 被限速 ⇒ −18.5 / −2.07 砸地。**限速只在接触时生效** |
| 6 | FLIP 段不给升力 | 纯自由落体 1.9 s 掉 42 m。**翻滚要边翻边吊** |
| 7 | FLIP `rCmd` 漏 `ROLL_SIGN` | 一路**加速**旋转 ⇒ theta 冲到 −933°、wz −17 |
| 8 | FLIP 目标角写死 180° / 又改成 `abs(eRoll)` | 前者俯仰倒扣时残留 26°；后者只滚 26° ⇒ 最终用「固定 180° + 边翻边修俯仰」 |
| 9 | FLIP 退出写了 `or c.any` | 车刚出赛道口时旁边还是跑道 ⇒ 一帧就退出（theta=0） |
| 10 | 出赛道判据用 `contact.air`（离面 0.2 m） | 颠簸就误触发 ⇒ 必须用 **`hasHit==false`（`.lost`）** |
| 11 | 弹射判据用「vy 大 + 水平速度小」 | 竖直爬坡时水平速度天然≈0 ⇒ 连续三次误杀。**改用竖直加速度且只在大吸力下生效** |
| 12 | 守卫的动作用「退出程序」 | 任务直接作废。**只能退化控制量** |
| 13 | 光学传感器当红石读 | 它的红石是**模拟量**（∝ 距离），只在 `POWERED` 时输出、背面不输出 ⇒ 改读**外设** `hasHit/getDistance` |
| 14 | 电脑磁盘 1 MB + `usedSpace` 是缓存 | 主机侧删文件**无效**；`fs.open` 返 nil 而不报错。用 `fs.delete`（`tests clean`）或重载世界 |
| 15 | 引擎是**蒸汽引擎** | 温度锁定不是限制，**燃料烧干 ⇒ 全部推进器瞬间失推力** ⇒ −29.59 砸地。已加 `[eng] fuel=xx%` |
| 16 | `peripheral.getType(<wrapped>)` 返回 nil | `tests id` 里的 `type=?` **不代表设备缺失** |
| 17 | 一次大文件读取会截断 | **改 memo 时绝不“读全文再写回”**，只用 `edit` 追加；惨痛教训见本节 |
