## 1. 目标

## 2. 已确认的物理事实（改写进 .design_guide/aircraft.md 的依据）
- 游戏气动 ≠ 现实：力方向**机体固定**、大小 ∝ 局部气流速度 v（线性非 v²）、攻角效应只来自 **(n·v)** 项；
- **对称帆 = 风向标式 α 弹簧**：法向阻力 (n·v) 是奇函数 → 放重心后方即可**双向静稳定**，"升力中心在重心之后"规则是现实航空学的误移植，已在指南中改写（`α 敏感面（尾翼）vs 重心` 行）；
- 普通帆升力方向恒沿 +n（体固定）、大小随 |n·v|² 减小（偶函数）→ 机翼纵向位置只管配平、不提供双向刚度；
- 全部气动力矩 ∝ 气压 P = e^(−0.004·(y−海平面)) → 高空（300 m ≈ 0.39）刚度与阻尼自动减半以上。

## 3. 飞行数据记录器（已实现，可进游戏用）
- 主文件：`src/main/java/com/zzy205/myfirstmod/compat/cc/FlightDataRecorder.java`
- 入口：`CCPeripheralExtender` 挂 `ServerTickEvent.Post`；停止时 `closeAll()` + `BodySensorRegistry.clear()`
- 配置：`Config.flightDataRecorderEnabled`（默认 true）/ `flightDataRecorderIntervalTicks`（默认 1 = 20 Hz）
- 输出：`<gameDir>/flight_logs/flight_<维度>_<bodyUuid前8>_<起始tick>.csv`，**每个 FMC（含 AIC）机体一个文件**；表头只在建文件时写 → **改代码后必须重启游戏再飞**
- CSV 列分组（顺序见 HEADER）：
  - 运动学/环境：tick、time_s、机体位姿（x/y/z、四元数）、pitchDeg/rollDeg/yawDeg、世界线速度 + |v|、世界角速度 w、机体系角速度 wb、静压孔平均 pressure/altitude、皮托管 airSpeed/groundSpeed、massKg/chainMassKg、com（世界 + 相对原点）、chainComRel
  - 受力（主机自身）：lift/drag/prop × (Fx,Fy,Fz,Mx,My,Mz) —— Sable 力组点力重算，机体局部系，M 绕该体 plot 质心
  - 受力（**整链**）：chainLift/chainDrag/chainProp × 同上 —— 链上全部 ServerSubLevel（含 aero_bearing 从动尾翼/副翼）的点力转世界系求和、绕**主机世界质心**求矩、再转回主机局部系（图纸看不到的部分就在这）
  - 控制输入：joyCh/joyX/joyY/joyXA/joyYA（摇杆2 频道 7）、thrCh/thrAxis/thrGear/thrFwd/thrBack（油门 频道 8）、pedCh/pedL/pedR（脚踏板 频道 6）——频道常量在 FlightDataRecorder 顶部，接线变了改这里
- 配套改动：`SableCompat.getLinearVelocity()`、`SableCompat.getCenterOfMassPlot()`、`BodySensorRegistry.fmcBodies(server)`/`clear()`
- **机制要点**：
  - 力组只在 `enableIndividualQueuedForcesTracking(true)` 时被 Sable 填充——记录器每 tick 对主机**整条约束链**幂等开启、文件关闭时对当前链恢复 false（与 Simulated 图纸同款开关；同开图纸时记录器关闭会连带关掉图纸的）
  - 力组按注册表 id 匹配（sable:force_groups 的 lift/drag/propulsion），未直接引用 `ForceGroups` 类（其字段类型引用 veil `RegistryObject`，不在编译 classpath）
  - 采样 = 游戏 tick 末，读到的是该 tick **最后一个物理子步**的力组；单位是 Sable 每物理步冲量刻度 → 看趋势/力矩平衡，勿当绝对牛顿值
  - 全 nan 排查：先确认重启过；再查注册表匹配/跟踪开关
- 分析脚本（Python，纯 csv 模块）：`run/flight_logs/_analyze_flight.py`、`_analyze_flight2.py`、`_analyze_flight3.py`、`_analyze_flight4.py`、`_analyze_flight5.py`、`_analyze_flight6.py`

## 11. 重大修正：chain 力矩的"恒定残余 ≈ +8"是**参考点假象**（_18/_9/_20 复核）
> 触发：用户用 windtunnel 多物理体模式把升力中心调到≈重心，chainLiftMx 却仍 +15~20 且 ∝P → 检查发现记录器力矩参考点用错了。

### 11.1 发现
- **链质心 ≠ 主机质心**：主机（含机翼/螺旋桨）质心 comRel≈(0,0,0)（=plot 原点），**整链**质心 chainComRel≈(0,+0.075,−0.950)——尾部子体（舵面等）占 ~15% 质量，把链质心拉到主机质心**后方 0.95 m、上方 0.075 m**；
- 记录器整链力矩（chainLiftMx 等）绕**主机**世界质心求矩（`appendChainForces` 用 `getCenterOfMass(sub)`），**不是**链质心 → 升力 F≈(+0,+14,0) 作用在主机质心前/后 0.95m 处时，凭空产生 **M = r×F ≈ 0.95×14 ≈ +13 的假力矩**；
- 升力 ∝ P → 假力矩也 ∝P → 看起来就是"残余抬头力矩随高度漂移、低空放大 2.4×"——**全部是参考点算错的产物**。

### 11.2 修正验证（力矩平移到链质心：M' = M − r_off×F，r_off = 链质心−主机质心）
| 数据 | 绕主机质心 净Mx | 绕链质心 净Mx |
|---|---|---|
| _18 300m 巡航 (P 0.39) | +8.69 | **−0.02 ≈ 0** |
| _9 TRIM=14 低空 150-200m (P 0.67) | +7.69 | **−0.85 ≈ 0** |
| _9 TRIM=14 高空 250-310m | +7.10 | +2.49 (n=8, 少) |

→ **用户配平正确：升力线≈过链质心，飞机净俯仰力矩≈0**。§8.3/§9.3/§10 里"净 Mx ≈ +8 恒定残余、必有未进力组的力矩抵消"的结论**作废**——那个 +8 是测量参考点错误。

### 11.3 真正的"低空抬头"来源仍未定（参考点假象排除后）
- 用户实测：低空松手会抬头爬升；**PITCH_TRIM_OFFSET=14（低头舵角）可压住**；
- 修正后净 Mx≈0 → 不是静配平残余力矩 → 候选改为：**舵面/配平执行、约束伺服、升力-阻力随 P 的非线性、或 chainLiftFy 与参考点不完全对齐的残差**（_9 低空 −0.85 vs 高空 +2.49，方向/量级与 P 的关系待干净低空数据）；
- ⚠ 记录器整链力矩参考点应改为**链质心**（与 Sable 动力学/风洞多物理体重心一致）再复测——Java 改动：`appendChainForces` 用 `getChainCenterOfMassLocal` 对应世界点。

### 11.4 符号约定最终确认（用户口头，覆盖 memo §4 的模糊地带）
- `ss.getAngles().pitch` / CSV pitchDeg：**低头=+、抬头=−**（用户实测 API 值）；

## 12. 俯冲-松手改出测试结论：机头自动抬升 = 正常静稳定改出 + phugoid（_21，TRIM=0，链质心参考已生效）
> 用户：TRIM=0，只做俯冲，俯冲后松手机头自动抬升。78 s / 1554 行，多次俯冲-拉起循环。

### 12.1 数据（段 A t 20.9–29.4：y 238 俯冲底松手）
- 松手瞬间 dragMx **−32**（舵面回中瞬态），随后净 Mx ≈ **−0.1~−0.5（≈0）**，liftMx 恒 ≈ **−0.1**（旧数据 +14~20 已消失 → 参考点修正生效，配平正确）；

- t 29.1 dragMx +32 尖峰 = 用户推杆主动压机头（非自动）。

### 12.2 结论
1. **静态配平正确**（净 Mx≈0，chainLiftMx≈−0.1）：无需 TRIM=14——之前"TRIM 压住抬头"压的其实是改出后的自然 phugoid 爬升；
2. **俯冲松手机头自动抬升是正常气动行为**（对称帆尾翼 α 弹簧改出 + 惯性过冲），真实飞机同样如此；
3. 若用户觉得"难保持高度/平飞"，症结是 **phugoid 周期长（~16 s）** → 已有俯仰人工阻尼环（GAIN=0.5，SIGN=−1）在 _20 高空验证有效（ζ −0.02→+0.033）；本趟 TRIM=0 且阻尼环仍开启。

## 13. 新需求方案：不同高度稳定巡航（计划，待用户确认后实施）
> 用户需求："想要能在不同高度稳定巡航"。触发背景：低空满油门松手自动抬头爬升、高空需更快空速才够升力——已确认不是配平/力矩缺陷，而是**游戏气动"升力 ∝ P×空速"造成的空速-高度耦合**。

### 13.1 物理机制（方案依据）
- 游戏气动：普通帆升力 ∝ P×|v|（P = 气压，随高度指数衰减；300 m ≈ 0.39、100 m ≈ 0.83）；
- 平飞需 升力 = 重力 → **维持平飞所需空速随高度变化**：高空 P 小 → 需更快空速；低空 P 大 → 同样空速升力过剩 → 自动抬头爬升；
- 用户只有俯仰（升降舵）控制，**没有空速/油门闭环** → 松手后空速由油门+阻力决定，低空时该空速对应的升力 > 重力 → 爬升。真实飞机靠飞行员管理空速/油门解决。
- 螺旋桨推力也 ∝ P（`BlockEntityPropeller`：thrust ∝ airflow scaling × air pressure）→ 高空推力自动变弱，加剧"高空掉速/掉高"。

### 13.2 方案（按投入递增，可组合）
1. **方案 1：手动巡航技巧（零代码，验证概念）**
   - 不同高度用不同空速：低空**收油降速**（~40 m/s 量级）再松手 → 应能平飞；高空**全油**高速补升力；
   - 目的：验证"问题 = 空速耦合"模型是否正确（若低空降速后能平飞 → 模型确认）。
2. **方案 2：空速保持环（auto-throttle，Lua，推荐起点）**
   - `err = 目标空速 − ss.getAirSpeed()` → 油门 = 基准 + Kp·err（Kp 可调）；
   - 目标空速来源：monitor KNOB 模块（`KnobModuleHandle.getNormalized()` 等已有 API）；
   - 效果：油门自动稳住空速 → 升力固定；但高度仍需手动选（"该高度所需空速"由人设定）。
3. **方案 3：高度保持环（altitude hold，最接近"稳定巡航"）**
   - 外环：`目标高度 − 当前高度 → 目标垂直速度`；内环：垂速误差 → 俯仰角指令（复用现有俯仰阻尼环做内层）；
   - **物理前提**：只用俯仰做高度保持会与 phugoid 耦合（抬头爬升→减速→失速→俯冲振荡）→ 高度环必须与空速保持一起做（= 方案 2 + 外环）才稳；
   - 目标高度来源：KNOB 旋钮；开关：TOGGLE 模块（同 auto_roll 的接线模式）。

### 13.3 待用户确认
- [ ] 高度保持做到什么程度：方案 2（手动调油/选目标空速，仅稳住空速）还是方案 3（设定目标高度后全自动维持）？
- [ ] monitor 上有几个可分配 KNOB/TOGGLE？（建议：目标高度 knob ×1、auto_alt toggle ×1、目标空速 knob ×1——若不够则方案 3 退化为固定高度硬编码）
- [ ] `ss` 无 `getVerticalSpeed` API——垂速需对 `getAltitude()` 做数值差分（20 Hz 下可用），确认可接受；或需要加 Java API（`SensorSystemAPI` 加垂速缓存列，需重启）。

### 13.4 相关现状（已查）
