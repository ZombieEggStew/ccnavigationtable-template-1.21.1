## 1. 目标
定位用户在游戏（Simulated/Sable + ccpe 航电）里造的固定翼飞机的问题：
- **低空翘头冲高**、**高空（205 m → 重做后 300 m）缓慢沉浮振荡（phugoid）**；
- （次要）高速大俯仰角时副翼剧烈抖动 + "着地"声（未定位）。

手段 = Java 服务端**飞行数据记录器**（只读，不改物理），CSV 落盘后用 Python 分析。

## 2. 已确认的物理事实（改写进 .design_guide/aircraft.md 的依据）
- 游戏气动 ≠ 现实：力方向**机体固定**、大小 ∝ 局部气流速度 v（线性非 v²）、攻角效应只来自 **(n·v)** 项；
- **对称帆 = 风向标式 α 弹簧**：法向阻力 (n·v) 是奇函数 → 放重心后方即可**双向静稳定**，"升力中心在重心之后"规则是现实航空学的误移植，已在指南中改写（`α 敏感面（尾翼）vs 重心` 行）；
- 普通帆升力方向恒沿 +n（体固定）、大小随 |n·v|² 减小（偶函数）→ 机翼纵向位置只管配平、不提供双向刚度；
- 全部气动力矩 ∝ 气压 P = e^(−0.004·(y−海平面)) → 高空（300 m ≈ 0.39）刚度与阻尼自动减半以上。

## 3. 飞行数据记录器（已实现，可进游戏用）
- 主文件：`src/main/java/com/zzy205/myfirstmod/compat/cc/FlightDataRecorder.java`
- 入口：`CCPeripheralExtender` 挂 `ServerTickEvent.Post`；停止时 `closeAll()` + `BodySensorRegistry.clear()`
- 配置：`Config.flightDataRecorderEnabled`（默认 true）/ `flightDataRecorderIntervalTicks`（默认 1 = 20 Hz）
- 输出：`<gameDir>/flight_logs/flight_<维度>_<bodyUuid前8>_<起始tick>.csv`，**每个 FMC（含 AIC）机体一个文件**；表头只在建文件时写 → **改代码后必须重启游戏再飞**
- CSV 列分组（顺序见 HEADER）：
  - 运动学/环境：tick、time_s、机体位姿（x/y/z、四元数）、pitchDeg/rollDeg/yawDeg、世界线速度 + |v|、世界角速度 w、机体系角速度 wb、静压孔平均 pressure/altitude、皮托管 airSpeed/groundSpeed、massKg/chainMassKg、com（世界 + 相对原点）、chainComRel
  - 受力（主机自身）：lift/drag/prop × (Fx,Fy,Fz,Mx,My,Mz) —— Sable 力组点力重算，机体局部系，M 绕该体 plot 质心
  - 受力（**整链**）：chainLift/chainDrag/chainProp × 同上 —— 链上全部 ServerSubLevel（含 aero_bearing 从动尾翼/副翼）的点力转世界系求和、绕**主机世界质心**求矩、再转回主机局部系（图纸看不到的部分就在这）
  - 控制输入：joyCh/joyX/joyY/joyXA/joyYA（摇杆2 频道 7）、thrCh/thrAxis/thrGear/thrFwd/thrBack（油门 频道 8）、pedCh/pedL/pedR（脚踏板 频道 6）——频道常量在 FlightDataRecorder 顶部，接线变了改这里
- 配套改动：`SableCompat.getLinearVelocity()`、`SableCompat.getCenterOfMassPlot()`、`BodySensorRegistry.fmcBodies(server)`/`clear()`
- **机制要点**：
  - 力组只在 `enableIndividualQueuedForcesTracking(true)` 时被 Sable 填充——记录器每 tick 对主机**整条约束链**幂等开启、文件关闭时对当前链恢复 false（与 Simulated 图纸同款开关；同开图纸时记录器关闭会连带关掉图纸的）
  - 力组按注册表 id 匹配（sable:force_groups 的 lift/drag/propulsion），未直接引用 `ForceGroups` 类（其字段类型引用 veil `RegistryObject`，不在编译 classpath）
  - 采样 = 游戏 tick 末，读到的是该 tick **最后一个物理子步**的力组；单位是 Sable 每物理步冲量刻度 → 看趋势/力矩平衡，勿当绝对牛顿值
  - 全 nan 排查：先确认重启过；再查注册表匹配/跟踪开关
- 分析脚本（Python，纯 csv 模块）：`run/flight_logs/_analyze_flight.py`、`_analyze_flight2.py`

## 4. 符号约定（解读数据前必读）
- **pitchDeg：低头 = 正、抬头 = 负**（用户实测 `ss.getAngles()`）——⚠ 与 `SensorSystemAPI.computeAttitudeDeg` 代码注释"pitch 正 = 抬头"矛盾，待进游戏对照订正（注释或约定二选一）；
- roll/yaw、wb 均机体系；CSV 与 `ss.getAngles()` 同一公式同源。

## 5. 已分析数据结论（flight_overworld_00b1000b_21.csv，重做后的飞机，300 m）
- 巡航段（y 245–355）：p50 pitch −0.6°、空速 61 m/s、压力 p50 0.396、垂速 ±11 m/s；
- **300 m 是轻阻尼 phugoid**：周期 12–44 s（稳定后 ~25–30 s，理论 ~2πv/(g√2)≈27 s）；峰谷幅值 75→22 m，衰减率 ≈0.009/s（幅值减半 ~77 s）；俯仰-爬升率相关 −0.81（机身跟航迹 = 风向标行为，非发散）；
- 尾段 pitch +40°、空速掉到 33 是降落俯冲，分析时剔除（t≈164 s 后）；
- 结论：**静稳定 OK（尾帆 α 弹簧有效），问题是阻尼不足** + 残余抬头力矩 ∝ P 随高度漂移（推力线在重心之上的结构问题仍在）。
