## 3. 物理预算（★ 这一节决定"能不能做到"，先看）

### 3.1 推力模型（文档公式）

```
单管推力 F_i = 转速(RPM) × 气压 p(y) × 出力系数 u(0..1) × 2      [pN]
满出力    F_max(y) = N × RPM × 2 × p(y)                          [pN]
重量      W = 11 × m                                             [pN]   ← G=11 m/s² 为实测常量
推力重量比 TWR(y) = F_max(y) / W
```

### 3.2 ★ 头号硬约束：**从"云端"下落时气压缩减会把 TWR 压死**

这是本场景最大的物理风险，必须**先算再搭程序**。

- 本 mod 大气模型实测锚点（`memo/flip-autopilot.md` §12.2，世界海平面 y≈63）：
  **y≈102 处 p ≈ 0.862**；往上继续下降。精确值请用 Lua 直接查：
  `ss.getPressureFromAltitude(Y)`（FMC 门控）或静压孔 `ss.getPressure()`。
- 着陆剖面要求：`F/m ≥ G + A_BRK_MAX = 11 + 5 = 16 m/s²` ⇒ **TWR ≥ 1.45**，
  留 25% 权限余量 ⇒ **实际要求 TWR ≥ 1.6**（在**开始点火的那个高度**上）。
- 由此得到**设计方程**（拿你的真实数据代入即可判定可行性）：

```
                N × RPM × 2 × p(y_drop)  ≥  16 × m
  等价：        N × RPM  ≥  8 × m / p(y_drop)
```

- 示例（**占位数字，等 `CALIB` 实测替换**）：
  | 情形 | N | RPM | m | p(y_drop) | 可用 TWR | 结论 |
  |---|---|---|---|---|---|---|
  | 8 管 @256，200 kg，y=190 | 8 | 256 | 200 | ≈0.60 | **1.12** | ❌ 连悬停都不够 |
  | 8 管 @256，200 kg，y=140 | 8 | 256 | 200 | ≈0.75 | 1.40 | ⚠️ 勉强，剖面跑不完 |
  | 12 管 @256，200 kg，y=140 | 12 | 256 | 200 | 0.75 | 2.09 | ✅ |
  | 8 管 @256，100 kg，y=190 | 8 | 256 | 100 | 0.60 | 2.24 | ✅ |

**⇒ 三条可选出路（需要你选）：**
1. **加喷管 / 减重**（力度最大，直接改 TWR）；
2. **降低起始下落高度**（`h_flip` 下移；横躺段少掉一段高度）；
3. **横躺段就用锥角产生 0.26×F 的"竖直分量"预先刹车**（见 §3.3，代价是水平方向乱飘）。

### 3.3 横躺时的可用竖直推力（提前刹车的唯一手段）

机体横躺时喷管轴是**水平**的，锥角可以把它偏到"世界竖直"方向，于是：

```
横躺时竖直可用推力  F_v = F × sin(15°) = 0.259 F
横躺时竖直可用加速度 a_v = 0.259 × TWR × 11
```

⇒ TWR=2 时横躺也能有 **≈5.7 m/s²** 的竖直减速（相当于 0.52 g），能显著压缩下落速度。
代价：同一时刻横向也有 0.259 F（会往旁边飘），且**与翻转力矩的方向需求可能冲突** → 优先级
"先拿力矩翻正，翻正过程中顺带用余量刹车"。

### 3.4 翻转权限（横躺 90° → 正立）

力矩来自**锥角横向分量 × 力臂**（喷管沿机体轴到质心的距离 r）：

```
τ = F × sin(15°) × r        α_flip = τ / I_hash ≈ τ / (m·L²/12)
90° 翻转（加速+减速）     t_90 ≈ 2·√(θ/α)  = 2·√(π/2 / α)
翻转期自由下落掉高        Δh ≈ ½·11·t_90²  （不出竖直推力时）
```

| L（机体长） | TWR | r≈L/2 | α_flip (rad/s²) | t_90 (s) | 掉高 (m) |
|---|---|---|---|---|---|
| 10 m | 2.0 | 5 m | ≈3.4 | 1.36 | ≈10 |
| 20 m | 2.0 | 10 m | ≈1.7 | 1.92 | ≈20 |
| 20 m | 1.5 | 10 m | ≈1.3 | 2.2 | ≈27 |

> 参照：你 `flip-autopilot` 里那台车实测 **α_roll = 8.99~12.1 rad/s²** 才把 180° 空翻压进 1.0~1.5 s。
> 火箭长、惯量大、**α 会小得多** ⇒ **翻转必须提前（留 20~30 m）**，这是本场景第二个硬约束。
>
> 若 `α_flip` 实测不足，提升顺序：① 差动出力（`setThrustScale` 两组不等）叠加同向偏转 →
> ② 喷管外移（r 变大，但受结构限制）→ ③ 减 L / 减重 → ④ **降低起始高度让 `vy` 更小、留更多时间**。

### 3.5 横向权限与落点精度

```
a_lat_max = 0.259 × TWR × 11   （TWR=2 时 ≈5.7 m/s²，但随油门同步缩小：与竖直推力共用同一份 F）
```

- 下落可用时间 ≈ 5~8 s（剖面参数下）⇒ 横向可修正距离 ≈ `½·5.7·t²` ≈ 70~180 m。
  **⇒ 指定点离初始水平位置 100 m 以内是舒适的，越远越依赖提前倾斜。**
- 落点精度目标：贴 `memo/flip-autopilot.md` §44/§49 水平（**XZ 残差 ≤ 0.5 m**），
  该 memo 实测能到 0.07~0.35 m（那是地面低速场景，空中要打折）。

### 3.6 悬停油门（用于 sanity check）

```
u_hover = 11·m / F_max(y) = 1 / TWR(y)
```
TWR=2 ⇒ 悬停约 50% 出力；TWR=1.5 ⇒ 67%。**悬停油门 > 85% 就别做了**（没有姿态/横向余量）。

## 5. 控制方案

### 5.1 总则（沿用已验证结论，不要重新发明）

1. **姿态一律走四元数**：欧拉角过 90° 会进奇异保护分支（横躺正好是 90° 附近！）——
   `memo/my_aero_sensor.md` / `flip-autopilot` §2.1。
2. **机体角速度自己差分四元数**，不要用 `getAngularVelocity()` 的分量轴（轴映射与文档不符）。
3. **写出推力前做 `cosVert` 门控**：`cosVert = 机体上·世界上`，`< COS_MIN(0.25)` 时**不许出集合推力**，
   否则"越推越快下坠"（`flip-autopilot` §18.2 的致命坑）。
   注：本场景"横躺"就是 `cosVert≈0`，所以**翻转段几乎全程处在门控区** ⇒ 翻转必须**靠差动/偏转出力矩**
   （力矩不需要集合推力）。这是设计上最微妙的一条。
4. **cos 补偿**：推力沿喷管轴，竖直分量 = `F·cos(倾角)`；深倾斜时要 `/cos` 放大。
5. **写预算**：每控制周期只有**一个** `parallel.waitForAll` 写块，块后**绝不 sleep**（20 Hz）。

### 5.2 各环律

| 环 | 律 | 初值（可调） |
|---|---|---|
| 姿态（FLIP） | 四元数误差 → `eRoll/ePitch`、`ω` 差分 → `u = KP·e − KD·ω`（饱和到 α_flip） | `KP_ATT=16, KD_ATT=8`（车的实测值，空中按实测 α 折算） |
| 竖直（BRAKE/HOLD） | `aDes = clamp(A_REF·FF + KV·(vyRef−vy), −A_ACC, A_BRK_MAX)`；`F = m(G+aDes)/cos`；`u = F/F_max(y)` | `A_REF=4, A_BRK_MAX=5, A_ACC=6, KV=6, H_SOFT=1.2, VY_TOUCH=0.8`（**已验证落地 0.65~0.70 m/s**） |
| 定高悬停 | `vyRef = clamp(K_POS·(hTarget − h), ±VY_HOVER)`（**不能复用落地剖面**，§15.2 的坑） | `K_POS=0.9, VY_HOVER=3.5` |
| 横向（GUIDE） | 位置环 → 期望水平速度 → 速度环 → 期望水平加速度 → 偏转量 `hfrac = a/(aFull·sin15°)` | `hKP=0.35, hKV=2.5, hVMax=3, hAMax=2, hMax=0.85` |
| 安全 | `cosVert < COS_MIN` / 无喷管 / 双曲率异常 → 关机 | — |

### 5.3 `setInverted` 在这里怎么用（你选了"用反推"）

本场景没有 boostback，但 inverted 有两个正当用途：

1. **上升超调制动**：悬停/逼近夹持点时若机体还在**上升**（`vy > +阈值`），正向推力会越推越快，
   这时 `setInverted(true)` 让力沿轴反向（= 向下）把它按回去，比"关机等它自己掉"更快更稳。
2. **姿态恢复期的双向力矩**：`cosVert≈0` 无法出集合推力时，`invert` + 锥角组合可以给出
   **两个方向的力矩**（同一组喷管在 15° 锥内左右推），比单向更省时间。

⚠️ **待实机确认的两条符号事实**（不确认就定不了稿）：
- `setInverted` 翻转的是**整根轴的力** ⇒ **锥角产生的横向分量一起反向**（Lua 侧要跟着取反）。
- 若实测发现四组喷管的极性不统一（`flip-autopilot` §11.7 就踩过"每通道符号不一致"），
  要改用"逐喷管极性表"而不是统一 `invert`。

### 5.4 `setDirection` 的坐标系坑（★ 目前最大的不确定项）

文档：`setDirection(x,y)` 的方位角 **0° = 模型 +X**，且"整个坐标系随方块的 FACING 一起旋转"；
**Lua 读不到方块朝向** ⇒ 我无法从程序里知道"偏转 +x 会把机体往世界哪里推"。

**解决办法（一次标定，之后写进 CFG）**：悬停中给全部喷管 `setDirection(1,0)` 保持 1.5 s，
用 INS 测水平加速度的世界方向 α，则模型系偏置 `frameYawOff = α − yaw`。
这一步和 `flip-autopilot` §37 的横向标定是同一套路，**必须先做**（否则横向环符号随机）。

## 8. 风险与未定项（定稿前必须清掉）

1. **TWR 是否够**（§3.2）——**唯一可能直接否决整个方案的项**。T1 一出结果就能判定。
2. **`setDirection` 坐标系**（§5.4）——不做 T2，横向环等于瞎飞。
3. **`setInverted` 的符号与横向分量反向**（§5.3）——需要一次 0.5 s 的静态/悬停对比测试。
4. **翻转权限 α_flip**（§3.4）——T5 才知道；不够就要改结构或改起始高度。
5. **机体原点 ≠ 质心**：下落/翻转时 `getBodyPosition()`、`getVelocity()` 会被 `ω×r` 污染
   （`flip-autopilot` §19.3），翻转段的 `h/vy` 只能当趋势用，**精确高度留给姿态回正之后**。
6. **横躺段的重力力矩**：若质心不在原点垂线上，横躺会一直自转，PD 要预留权限。
7. **"夹住"只是视觉**：程序结尾是悬停 + 关机 + 打印；不驱动任何夹持机构（要真夹持另做）。

3. **`getOrientation()` 的符号不保证 w>0**（火箭侧实测 `w = −1`）⇒ 所有四元数运算入口先做

4. **反推必须按"相对基准反转"**：基准是 ch0=inverted、ch1~4=!inverted。
   `setInverted` 全组写同一个值会把中心喷管翻错方向。
5. **`getPhysicsMass()` 已经是本机质量**（不是链质量）⇒ 推力/重力预算直接用 61 kg，不需要等释放。

### 12.2 为什么这样设计（两条关键取舍）

- **喷管外设引用在开头缓存一次就不再重查**：释放后两个物理体分链、频道会重新登记（≤20 tick），
  但喷管本身在火箭那一体上没有变动 ⇒ 缓存的外设对象仍然有效，控制环不会因为重登记而断掉。

### 15.2 ★ 根因：**横向阻尼环本身把机体掀翻了**（正反馈）

链路（每一步都有实测支撑）：

```
用 setDirection 横向阻尼 (v4 的 dampK=0.6)

   -> 机体歪掉
   -> 推力沿歪掉的机体轴 => 出现横向力（sin(tilt)·a_thrust）
   -> vx 变大 => 阻尼指令更大 => 偏转更大 => 力矩更大 => 翻车
```

**⇒ 这与用户的观察完全同源**：连接器不是同时断开 → 起飞瞬间给一点点倾斜/侧向速度 →
**一旦有倾斜，竖直推力就会持续把它侧推**（TWR 3.4 意味着横向泄漏也放大约 3.4 倍）。
第 2 次飞行（v3）那个"恒定 1.2 m/s² 漂移"就是 cosVert≈0.989（倾斜 ≈8.4°）的推力横向分量，
`sin(8.4°) × a_thrust ≈ 1.4 m/s²`，与实测 1.2~1.3 对得上 —— **不是寄生力，就是姿态**。

**结论：横向平移与姿态在这套执行器上是不可分离的（单一偏转通道同时给力和力矩）。
必须先有姿态闭环，横向制导才能用。** 这与真星舰用摆动发动机同时做平移+姿态控制是同构的。

## 18. ★ 目标剖面改为"复刻直播轨迹"（2026-11-17 用户描述）—— 架构变更

### 18.1 用户给出的真实轨迹（直播所见）

1. 助推器再入时是**横躺**的，**机头指向水平方向（0°）**，落点在**目标点后方**（实例：水平偏 69 m）；
2. 落到**云层下方**时**开启引擎**；
3. 姿态从 0° 改为**竖直（90°）**；
4. 随后出现**水平过冲**：机头指向**左上方 ~115°**（= 相对竖直再偏 25°）；
5. 然后回到竖直，抵达夹具附近被夹住。

### 18.2 架构上的结论（这条推翻了我之前的假设）

**机体倾斜才是主矢量手段**：

| 手段 | 横向分量 | 说明 |
|---|---|---|
| 15° **锥角**偏转 | `sin15° = 0.26` | 细调，权限有限 |
| **机体**倾斜 25° | `sin25° = 0.42` | 直播里那个 115° 姿态就是在做这件事 |

⇒ 真实着陆是"**姿态轨迹**"：`0° → 90° → 115° → 90°`，
竖直推力与横向推力由**同一个机体倾角**同时决定，`u` 与 `cosVert` 强耦合。
原来的 `starship.lua`（只做竖直 + 锥角横向）在这个剖面前是**结构性缺一块**：它没有姿态环。

### 18.3 为什么 `starship.lua` 这轮直接砸地（诊断已确认）

```
enter wait : h=119.46  cosVert = 0.0000   <- 横躺（用户描述的"机头水平"）
整个 burn 段 u = 0.0000                   <- cosKill(0.60) 门控把推力全切了（安全行为，正确）
FLARE h=-28.55  cos=0.00                  <- 自由落体到底面（地面 y≈64.5）
err = (+2.00, -69.45)                     <- 放手点离目标 69 m，横向权限本来就拉不回来
```

### 15.4 ✅ 喷管几何（用户提供）

| 喷管 | 位置 | 力臂用途 |
|---|---|---|
| ch0 | 中轴（无横向力臂） | 只加集合推力，**不产生力矩**；注意它 `inverted = true` |
| **ch1 / ch3** | **前 / 后** | 差动 ⇒ **俯仰力矩** |
| **ch2 / ch4** | **左 / 右** | 差动 ⇒ **滚转力矩** |

**⇒ 姿态与平移可以用两个正交通道同时闭环**（这是整套方案的关键）：

```
pitch   = ch1 与 ch3 的差动出力 (Δp)        净竖直推力不变
roll    = ch2 与 ch4 的差动出力 (Δr)        净竖直推力不变
lateral = 全部五台同向的 setDirection(锥角)  给横向力（附带力矩扰动）
                                     ↑ 扰动由上面两路差动抵消
```

出力分配（S = 集合出力，Δp / Δr = 力矩分量）：

```
ch0 = S
ch1 = S + Δp   ch3 = S - Δp
ch2 = S + Δr   ch4 = S - Δr
约束：S + |Δp| + |Δr| <= 1,  S - |Δp| - |Δr| >= 0
```

（决定力矩符号），用"单独把 ch1 打满、其余 0，测俯仰角加速度方向"就能定。
另外 `ch0 = S` 这一条天然是对的（中轴喷管没有力臂）。
