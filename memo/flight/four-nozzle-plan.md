## 1. 坐标系与三个必须记住的约束

- 机体：**X 左右、Y 上下、Z 前后（机头 −Z）**；`getForcePoint()` 的 `x/y/z` 就是力臂 `r_i`（原点=质心）。
- **约束 1**：`getForcePoint()` / `getSensors()` 是 `mainThread = true` ⇒ 每次调用占一个写块（约 1 tick）。
  **只在初始化读一遍并缓存**，绝不放进 20 Hz 控制环。
- **约束 2**：物理体原点 = 质心；**在机体上加/删方块后**原点会漂，旧 `r_i` 作废 ⇒ 改装后重跑 P0。
- **约束 3**：`setDirection(+x)` 的受力符号**不能从几何推**（两发实测与推导反号，黑名单 #14）。
  ✅ 2026-11-21 两发四发实测：**推力 = (−摇杆x, +摇杆y)**（x 轴 `sc=+1.02`、z 轴旧映射 `sc=−0.79~−0.92`）
  ⇒ 机体系映射 `setDirection(−dirx, +dirz)`，其中 `dirx/dirz` 是**期望推力方向**（黑名单 #37）。
  **两个分量符号不同**，别从一个推另一个。
  四台同向安装 ⇒ 全机一套映射，但**仍要一次实测**符号后才准开横向/偏航环。

传感器基线（用户 2026-11-21：**本仓所有载具都只装一台 AIC**）：AIC = INS + FMC 双登记，
姿态/角速度/速度/质量全可读；**没有皮托管、没有静压孔** ⇒ `getPressure()` 恒 nil，气压走
`getPressureFromAltitude(y)`；`ss.getStressRemaining/Capacity` 可能被门控成 nil ⇒ 应力看引擎的
`getStressUsed/Capacity`。程序只用这四个来源，不要再指望别的传感器。

## 2. 四发控制分配（本计划的核心，全部由 `r_i` 算，不手填）

记 `F_i = u_i·K_NOZ·p`（竖直、朝上），`τ = Σ r_i × F_i`：

```
τ_x = −Σ z_i·F_i        （俯仰：前后）
τ_z =  Σ x_i·F_i        （滚转：左右）
τ_y =  Σ (z_i·F_x,i − x_i·F_z,i)   （偏航：只能来自锥角）
```

| 通道 | 手段 | 分配公式 | 净侧效应 |
|---|---|---|---|
| 总距 `F_z` | 四台同增 | `u_i = u0` | — |
| 俯仰 `τ_x` | **前后推力差** | `u_i += α·(−z_i)/Σz²`，`α = Δτ_x/(K·p)` | 零横向力 |
| 滚转 `τ_z` | **左右推力差** | `u_i += β·(+x_i)/Σx²`，`β = Δτ_z/(K·p)` | 零横向力 |
| 偏航 `τ_y` | **四台切向锥角** | 方向 `t_i = (z_i, 0, −x_i)/L_i`，幅值 `F_t,i = γ·L_i` ⇒ `τ_y = γ·ΣL²` | `Σ F_t,i·t_i = γ(Σz_i, −Σx_i) = 0`（矩形居中时） |
| 横移 `F_x/F_z` | **四台共模锥角** | 四台同向 `setDirection`，幅值按 `F_h = F_i·sinθ` | `τ = (Σr_i)×F = 0`（矩形居中时） |
| 垂直损失 | 锥角 `θ` | `F_z` 乘 `cosθ`（15° 只掉 3.4%，可忽略，但高度环会看见） | — |

**与两发的本质区别**：

1. **滚转改由推力差直接控制**（两发被迫用同向锥角），锥角空出来专管偏航 + 平移；
2. 四台推力 = **4 输入 / 3 方程**（`F_z, τ_x, τ_z`）⇒ 多一个自由度，**常值偏置（质心偏、风扇效率差）可以配平**：
   等 u 悬停量出残余 `τ_x, τ_z` 后，`δu` 取 4×3 矩阵 `[1; −z_i; x_i]` 的最小范数解；
   两发只能给一个配平比 `r*`，这是四发真正多出来的东西；
3. 四台两两对称 ⇒ 共模锥角的力矩自抵消、切向锥角的横向力自抵消，**平移与转动解耦**（前提：P0 验矩形居中）。

**写入预算**：`4×setThrustScale + 4×setDirection` 放进**同一个** `parallel.waitForAll` = **1 tick**
（constants 黑名单 #21：块数= tick 数，块内条数不收费）。拆成两块才是 2 tick。

三个实现注意：

1. **锥角通道要按每台的 `u_i` 归一化**：`F_h,i = u_i·K·p·sinθ_i` ⇒ `θ_i = F_h,i/(u_i·K·p)`。
   做俯仰/滚转差动时四台 `u` 不同，若四台用同一个锥角，横向/偏航会带出额外力矩。
2. **垂直损失** `ΣF_i·cosθ` 进高度环前馈（15° 掉 3.4%）；横移加速时它会变成"掉高"。
3. `setDirection` 是 `-1..1` 的圆形摇杆（长度=锥角/15°）；四台同向安装 ⇒ 全机一套 body↔局部映射。
   **映射已实测**：`推力 = (−摇杆x, +摇杆y)`（黑名单 #37）；写控制律时统一用
   `setDirection(−dirx, +dirz)`，`dirx/dirz` 保持"期望推力方向"的语义，别在别处再翻一次。

## 7. 末端制动（制导末段按速度提前刹车）—— ✅ **v1.5 实机 PASS ×2（2026-11-22 00:35 / 00:36）收官**

**问题（现象）**：位置环是纯 PD `a = 0.28·e − 0.74·v`，接近时以 **1.0~2.3 m/s 穿过目标点**，
再冲出 **0.25~0.48 m**（短程）/ **2.05 m**（58 m 远程）才停住，然后慢慢挪回。

**根因（22:10 用 `temp/m4fly_brake_fit.lua` 独立复算 8 份归档 CSV，改判了原来的猜测）**：
- ❌ 不是"实机只拿到指令的 2/3"。实测减速度 **≈ 指令 + 阻力**：`v=2.5` 处 **0.95** vs 指令 0.80、
  `v=0.58` 处 **0.46** vs 0.45（"2/3"是没扣 `d·v` 的读法）。
- ✅ 是 **PD 自己到得太晚**：`0.28e−0.74v` 直到 **e=4.4 m** 才吃满 `A_CAP=−0.80`，此刻仍有 **2.55 m/s**。
- ✅✅ **而且巡航峰值随任务距离线性涨**（PD 的 `v≈0.38e` 段），可用减速度却恒定 ~0.9：
  33 m 发峰值 4.45 m/s（要刹 11 m）、58 m 发峰值 **5.82 m/s**（要刹 **18.8 m**）。见 #49/#50。

**做法（v1.4 落码 → v1.5 修正）**：CRUISE 内、世界系泄漏补偿之后、`A_CAP` 限幅之前，**只加刹车、不替代 PD**：

```lua
local vAllow = math.sqrt(2 * CFG.A_APP * e)      -- e = 到目标距离；v1.5 起没有距离门限
if vClose > vAllow then                          -- vClose = 速度在"指向目标"方向的分量
    aCmd = aCmd - CFG.K_BRK * (vClose - vAllow)  -- 沿 e_hat 反向追加刹车
end
```

| 参数 | 值 | 依据 |
|---|---|---|
| `A_APP` | **0.30 m/s²** | 实测可用 ~0.9 的 1/3，保守（`√(2·A·e)` 全程都在可刹范围内） |
| `K_BRK` | **1.50 /s** | 只做"多退少补"，不需要精确 |
| ~~`E_APP`~~ | **已删除** | v1.4 的 8 m 门限是灾难：8 m 内 PD 早已饱和（无料可加），而远程需要 19 m 的制动距离 ⇒ **58 m 发以 2.13 m/s 过点、冲出 2.05 m**（#50） |

- 只在 **CRUISE** 生效（PRE/SETTLE 在点上、速度为 0；HOLD/YAW 是 P5a/P5b 验过的行为，不动）；
- 第 5 参数 `off` 可**同场 A/B** 复现 v1.3 纯 PD（不跳任何其它分支），`<数值>` 可临时改 `A_APP`；
- status 多一行 `RES BRK`（峰值罚项 + 生效样本数），`temp/m4fly_fit.lua` 新增 `OVER`/`APPRO`/`HOLD3`/`BRAKE VERDICT`。
