# 水冷模块

![water_cooling_module](../img/water_cooling_module.png)

**水冷模块**（`ccpe:water_cooling_module`）是[引擎系统](overview.zh.md)的**液体散热模块**：自带 8000mb 冷却液储罐，为引擎牛顿冷却贡献固定散热分量（`K_WATER`）。

与[冷却气道](cooling-air-duct.zh.md)的本质区别：水冷的散热**不吃冲压（飞行速度）、也不吃气压（高度）**——液体回路不看空气。所以它是**静止、低速、高空**这三个「风道最弱」场景的解；代价是**要喝冷却液**，过热时还会加速蒸发，而且很重。


## 冷却液

| 项 | 规则 |
|---|---|
| 容量 | **8000mb 单槽**（只能装一种冷却液，换液需先排空） |
| 加液方式 | 流体管道/泵（方块暴露 `FluidHandler` 能力）；或**手持流体容器右键**（右键 = 物品→罐优先，潜行右键 = 罐→物品优先） |
| 只收冷却液 | 只接受 datapack `coolant/*.json` 表内流体。表外流体（岩浆、原油等）**装不进去**，手持容器也不会被消耗 |
| 拆除 | 内部冷却液**丢失**（不退回桶） |

!!! note "为什么只收冷却液"
    冷却液表就是白名单：既保证「装进去的东西一定有散热系数」，也避免把引擎当燃料/锅炉水的储罐（controller 的源扫描会跳过水冷模块）。

## 散热贡献

```
k_water = K_WATER × Σ_模块 [ min(液量 / 4000, 1) × 冷却液效率 ] × 回路开度
K_WATER = 0.33（每个模块满效）
```

- **加在散热公式的括号之外**：`K_total = (K_CORE×节数 + K_AMB×运行室 + K_DUCT×风道×风门) × ram(速度) × f(气压) + k_water`
  —— 所以水冷**与飞行速度、气压（高度）完全无关**（完整模型见[温度与冷却模型](temperature.zh.md)）。
- **液量曲线**：≥ **4000mb 满效**；4000mb 以下**线性衰减**；0mb = 0（平滑过渡，不会在 4000mb 处跳变抖动）。
- **冷却液效率**：数据包字段 `efficiency`（水 = 1.0，`aeronautics:levitite_blend` = 1.5）——直接乘进散热。
- **回路开度**：Lua `setWaterCooling(0..1)`（默认 1.0 全开）；0 = 关闭回路（既不散热、也不蒸发失液）。
- 多模块叠加：`k_water` 是所有工作中的模块之和。

### 沸腾期还会额外散热（蒸发潜热）

冷却液一旦在 **200°C 以上沸腾**，蒸发带走的就是**实打实的热量**（1 mB 水汽化 ≈ 2.26 kJ）——所以沸腾除了失液，还会降温：

```
heat_net = heat − EVAP_LATENT_GAIN × 20 × Σ(沸腾 mb/tick)
EVAP_LATENT_GAIN = BOIL_COOLING_PER_DEGREE ÷ COOLANT_BOIL_MB_PER_DEGREE_SEC = 1.5 ÷ 3.0 = 0.5 °C/s 每 mB/s
（等价写法：Q_evap = 1.5 × (T − 200)，即"每 °C 过热扣 1.5 °C/s"，与 k_total 同量纲）
```

- 这一项**不进 `k_water`**：它是质量流量项（∝ 失液速率），不随温差变化，所以**同样不吃冲压/气压/风道**。
- **T ≤ 200°C 时恒为 0** → 200°C 以下的一切既有平衡（风道、水冷散热、经济区、过冷惩罚）完全不变。
- **必须真烧冷却液才给这份散热**：蒸发速率与失液速率是同一份数值，不会出现「少烧水多散热」。
- 蒸汽引擎 / 回路关闭 → 0（那两种情况本来也不烧冷却液）。

**实测基准**（基准燃料 `heat=1.0`、**4 个满载流体燃烧室 + 1 个满罐水模块**、1 节核心、静态、海平面 → `heat=120`、`k_total≈0.55`）：

| | 平衡温度 | 沸腾失液 | 8000mb 续航 |
|---|---|---|---|
| 没有沸腾散热 | ≈238°C（**反复 220 硬停 / 200 重启**） | 0 | — |
| 有沸腾散热（现值） | **≈210°C（稳定）** | ≈30.9 mB/s | ≈4.3 分钟 |

!!! note "平台温度与续航是两个独立常数"
    - **`BOIL_COOLING_PER_DEGREE = 1.5`**（°C/s 每 °C 过热）**锁定平台温度**：`T − 200 = (heat − 180×k_total) / (该值 + k_total)`。
    - **`COOLANT_BOIL_MB_PER_DEGREE_SEC = 3.0`** **只决定烧多快（续航）**：满罐 ≈4.3 分钟。
    - `EVAP_LATENT_GAIN` = 两者相除 = **0.5**，即只承认 ≈29% 的纯潜热当量（≈1.74；其余随排放口/排气带走）——这是"缩短续航"的代价所在。
    - **玩家定稿**：蒸发维持高温只是**紧急方案，不允许长时间维持**。想要更长/更短只改失液速率，平台温度不会被带跑偏。
    - 燃料更热（柴油 `heat=1.25`）平台仍会抬到 ≈225°C 而过热——这时该加水冷模块或开富油，见下文。

### 定值依据：「1 个满罐水冷把 2 个满载流体室压到 ~150°C」

```
Q      = 2 室 × 满载(1.0) × 燃料heat(1.0) × BASE_HEAT_FLUID(30) = 60 °C/s
需要 k = Q / (150 − 20) ≈ 0.462
引擎自带 k_air = K_CORE×节数 + K_AMB×2 ≈ 0.12（1 节核心）~ 0.14（2 节核心）
K_WATER = 0.462 − 0.13 ≈ 0.33
```

海平面静止、2 室、燃料 `heat=1.0`、无风道、**2 节核心**（`k_air = 0.04 + 0.05×2 = 0.14`）时的平衡温度（`T_eq = 20 + Q/k`，`Q = 2 × 30 × 负载`；温度上限钳在 264°C）：

| 冷却液 | k_water | 满载 100% | 63% | 43% | 20%（怠速） |
|---|---|---|---|---|---|
| 无模块 / 无冷却液 | 0 | 448 → 钳 264（**过热**） | 290 → 钳 264（**过热**） | ≈204°C（即将过热） | ≈106°C |
| 2000mb 水（液量 50%） | 0.165 | ≈217°C（即将过热） | ≈144°C | ≈105°C | ≈59°C |
| **4000mb 以上水（满效）** | **0.33** | **≈148°C** ✅ | ≈100°C | ≈75°C | ≈46°C |
| 8000mb levitite（×1.5） | 0.495 | ≈115°C | ≈80°C | ≈61°C | ≈39°C |

（1 节核心的引擎 `k_air = 0.12`，同样满罐水冷满载约 **153°C**——所以「2 室满载 ≈150°C」在 1~2 节核心都成立。）

!!! warning "水冷很强：低负载会过冷"
    装了大水冷的引擎在低负载下会掉到 100°C 以下，进入**过冷**（油耗惩罚）。要么加负载，要么用 `setWaterCooling` 关小回路保热（0.5 ≈ 一半散热）。
    另外平衡温度还会被这些因素移动：**燃料 `heat` 倍率**（柴油 1.25 → 更热）、**引擎节数**、**风道数量**。

## 冷却液消耗

两种消耗同时存在（服务端每 tick 计算，累积到 1mb 才真正扣除）：

| 消耗 | 触发条件 | 速率 |
|---|---|---|
| **常态运行成本** | **引擎开着**（油门 ≠ 0 且未过热停机） | 每个工作模块 **每 8 秒 1mb**（满罐 ≈ 17.8 小时） |
| **过热沸腾** | **只要 T > 200°C**（「即将过热」以上，**不需要引擎开着**） | 每个工作模块每秒 `3.0 × (T − 200) × 自己的 boilMultiplier` mb —— 210°C ≈ 31 mb/s（满罐 ≈4.3 分钟） |

- **逐模块独立计账**：每个模块只攒自己的欠账、只扣**自己的罐**——装 N 个模块就是 N 个罐同时按各自速率掉液（不会出现「只掉第一个模块」）。
- 沸腾与温度**成正比**：200°C 整点速率为 0（无边界抖动），越热掉得越快。
- **过热硬停后仍在掉**：引擎到 220°C 会硬停（不烧油），但只要温度还压在 200°C 以上，冷却液就继续蒸发——而且冷却液越少 → 散热越弱 → 温度越高 → 掉得更快（正反馈）。满罐在 219°C 下约 14 分钟烧完，210°C 约 27 分钟。
- **停机不耗常态成本**：油门 0 停机时冷却液只受沸腾影响（语义同「停机不烧油」）。
- 回路关闭（`setWaterCooling(0)`）时两种消耗都停止——但散热也没了。

## 蒸汽引擎

水冷模块对**蒸汽引擎无效**：不参与其温度（闭式锅炉自调节，见[蒸汽动力室](steam-power-chamber.zh.md)），**也不消耗冷却液**。挂在蒸汽引擎上 = 摆设（引擎核心 goggle 会显示「水冷散热：无」）。

## 与冷却气道对比

| | 水冷模块 | 冷却气道 |
|---|---|---|
| 每块散热（满效） | **0.33**（≈ 6.6 块风道） | 0.05 |
| 冲压（飞行速度）加成 | **无** | 有（≤30 m/s 最高 ×2） |
| 气压（高空）惩罚 | **无** | 有（`气压^0.8`） |
| 运行成本 | 冷却液（8 秒 1mb / 模块） | 无 |
| 过热惩罚 | 冷却液加速蒸发 | 无 |
| 液体储罐 | 8000mb（只收冷却液） | 无 |
| 可调性 | `setWaterCooling` 回路开度 | `setCooling` 风门 |
| 最佳场景 | 静止、低速、高空 | 高速飞行、不要补给 |

## 数据包：冷却液

冷却液表位于 `data/<命名空间>/coolant/*.json`，`/reload` 热加载：

```json
{ "fluid": "minecraft:water", "efficiency": 1.0, "boilMultiplier": 1.0 }
```

| 字段 | 含义 |
|---|---|
| `fluid` | 冷却液流体 id（唯一键）。**表内流体 = 水冷模块的填充白名单** |
| `efficiency` | 冷却效率倍率（默认 1.0，必须 > 0）：直接乘进 `k_water` |
| `boilMultiplier` | 沸腾失液倍率（可选，默认 1.0，必须 > 0）：越大越容易在 200°C 以上蒸发损失 |

- 本模组自带：`minecraft:water`（1.0）、`aeronautics:levitite_blend`（1.5）。想加冷却液只需再加一个 json，**不用改代码**。
- 流体 id 与本档安装的 mod 解耦：写一个没安装的 mod 的流体 id 不会崩，日志里会提示「该流体未注册」，条目保留。

## Goggle 显示

**水冷模块自身**（戴 goggles 悬停）：

```
流体容器
  水 8000 mB / 8000 mB
冷却效率：×1.00
散热：+0.33
```

- 液量 < 4000mb 时「散热」行会追加「（液量不足，4000 mB 满效）」。
- 空罐 / 表外流体 → 冷却效率显示「无冷却液」，散热显示「无」。

**引擎核心**（装了水冷模块时多两处）：

```
发动机状态
…
负载：43%
水冷散热：+0.33            ← 无冷却液 / 回路关闭 / 蒸汽引擎 → 灰「无」
连接的模块：
- 流体燃烧室 x2
- 水冷模块 x1
```

!!! note "为什么模块自己不代理到核心"
    冷却气道的 goggle 会代理到引擎核心（显示引擎温度 + 风门）。水冷模块**故意不代理**：它的液位与冷却效率比引擎温度更重要，所以保留自己的流体 tooltip。想看引擎温度就悬停引擎核心。

## Lua API

新增的方法（详见[引擎 Lua API](lua-api.zh.md)）：

| 方法 | 说明 |
|---|---|
| `hasWaterCooling()` | 是否装了水冷模块 |
| `getWaterCooling()` / `setWaterCooling(0~1)` | 水冷**回路开度**（默认 1.0；0 = 关闭回路：不散热也不失液） |
| `getWaterCoolingPower()` | 当前有效水冷散热 `k_water`（含液量比例 / 效率 / 开度） |
| `getWaterCoolingModules()` | 工作中的水冷模块数（液量 > 0） |
| `getCoolantAmount()` | 冷却液总量 mb（工作模块合计） |

```lua
local e = peripheral.find("ccpe:engine")
print(e.getWaterCoolingPower())   --> 0.33
print(e.getCoolantAmount())       --> 8000.0
-- 低负载保热：关小一半回路
e.setWaterCooling(0.5)
```
