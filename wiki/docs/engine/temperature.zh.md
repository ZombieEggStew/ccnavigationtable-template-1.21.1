# 温度、高度与冷却模型

引擎温度是一个连续量，由引擎 controller **每 tick 在服务端**用**牛顿冷却模型**计算，并持久化到 controller 的 NBT。本页详解发热与散热的具体计算方式——包括驱动它们的**高度→温度**与**高度→气压**关系。

> 适用于**流体引擎**。**蒸汽引擎**不用这套模型——其闭式锅炉自调节（见[蒸汽动力室](steam-power-chamber.zh.md)）。

## 模型一览

```
发热      Q_heat = Σ运行室 × 发热负载 × 燃料.heat × BASE_HEAT_FLUID × heatFactor(m_eff)
          发热负载 = max(实际网络负载, 怠速下限 0.2)
蒸发散热  Q_evap = 1.5 × (T − 200)              ← 只在 T > 200°C 非零；从净发热里扣，不进 K_total
散热      P_loss = K_total × (T − T_amb)
                 K_total = (K_CORE×节数 + K_AMB×运行室数 + K_DUCT×风道数×风门) × ram(速度) × f(气压)
                           + k_water        ← 水冷模块：不吃冲压、不吃气压

积分      T += (Q_heat − Q_evap − P_loss) / C_th / 20      （每 tick；C_th = C_TH_BASE × 节数）
钳制      T ∈ [T_amb, OVERHEAT_TEMP × 1.2]
过热      T ≥ 220°C 硬停；T ≤ 200°C 恢复（滞回）
冷却液    常态：引擎开着时每工作模块每 8 秒 1mb；沸腾：只要 T > 200°C 每工作模块每秒 1.5×(T−200) mb
```

引擎在**发热 − 蒸发 = 散热**时达到平衡——**负载**、高度、冷却的任何变化都会移动平衡温度。油门只通过「抬高机器的应力需求 → 抬高负载」间接影响温度。

## 发热（Q_heat）

只有运行中的流体燃烧室发热，且仅在引擎运行、未过热时：

```
Q_heat = 运行室数 × 发热负载 × 燃料.heat × BASE_HEAT_FLUID(30) × heatFactor(m_eff)
```

| 项 | 含义 |
|---|---|
| `运行室数` | 正在燃烧的流体燃烧室数量 |
| `发热负载` | = max(实际网络负载, 怠速下限 0.2)——发热 ∝ **负载**，即「下游机器的已用应力 / 引擎可提供容量」 |
| `燃料.heat` | 燃料 datapack 条目的 `heat` 倍率（见[燃料](fuel.zh.md)） |
| `BASE_HEAT_FLUID` | **30 °C/s**——流体室基础热 |
| `heatFactor(m_eff)` | 混合比热因子（见下） |

### 混合比热因子

`m_eff = 杆 × autoRichness(气压)`（混合比杆与高空自动富油见[流体燃烧室](fluid-combustion-chamber.zh.md)）：

- **双侧统一线性公式**：`heatFactor = 1 − (m_eff − 1)`（即 `2 − m_eff`），斜率 −1，无凸曲线、无下限钳制。
- **拉稀**（`m_eff < 1`）：`heatFactor > 1`，越稀越热（`m_eff=0.8 → ×1.20`）。
- **富油**（`m_eff ≥ 1`）：`heatFactor < 1`，越浓越凉（`m_eff=1.4 → ×0.60`）。
- **高度自动浓稀 = 免费调温**：化油器按进气体积配油——高空天然变浓（`autoRichness` 最高 ×1.25）只降温（满自动富油时 `heatFactor` 最低 ≈0.75）；海平面以下高气压天然变稀（最低 ×0.75）只升温——**绝不费油**。

热因子只缩放**发热**——绝不反哺油耗（经济系数只乘消耗）。

### 负载与平衡温度

**负载** = 引擎所在应力网络的「已用应力 / 可提供容量」（详见[流体燃烧室](fluid-combustion-chamber.zh.md)页的「负载」小节）。

- 挂更多机器、或提高转速（每台机器的应力 ∝ 转速）→ 负载上升 → 平衡温度上升。
- 负载为 0 时仍按**怠速下限 20%** 发热（对应真实内燃机怠速油耗），所以空转的引擎会稳定在一个「略凉但温暖」的平衡温度，而不是降到环境温度。
- **满负载能不能维持，取决于散热**——这正是真实的「最大持续功率 < 最大功率」。

海平面静止、**4 流体室 + 2 冷却气道**（`k_total = 0.38`、`C_th = 4`、`BASE_HEAT_FLUID = 30`）的示例：

| 负载 | 平衡温度 | 说明 |
|---|---|---|
| 0%（怠速，按 20% 发热） | ≈83°C | 略低于 100°C 工作线 |
| 25% | ≈99°C | 刚跨过工作线 |
| 43% | ≈156°C | 经济带 145~165 |
| 63% | ≈219°C | 过热阈值 220 |
| 100% | ≈336°C（钳 264） | 静止满负载必然过热 |

同一套 4+2 配置下：**飞行速度 30 m/s（冲压 ×2）时满负载平衡温度只有 ≈178°C**；**Y≈260 高空（气压因子 ≈0.53，散热只剩约一半）时，负载 25% 就到 ≈169°C、负载 34% 就触到 220°C 过热线**——高空只能低转速或少挂机器。

计算方法：`T_eq = T_amb + 运行室数 × 30 × 发热负载 / k_total`。

## 散热（K_total）

```
K_total = (K_CORE×节数 + K_AMB×运行室数 + K_DUCT×风道数×风门) × ram(速度) × f(气压) + k_water
```

| 项 | 含义 |
|---|---|
| `K_CORE` | **每节 0.02**——引擎自身被动散热。**停机也一直生效**（所以停机的引擎会缓慢降温）。 |
| `K_AMB` | **每个运行室 0.05**——运行室的环境对流散热。停机的室不计（停机引擎只靠 K_CORE 散热）。 |
| `K_DUCT` | **每个冷却气道 0.05**——气道鳍片。按冷却**风门**（`setCooling`，见[冷却气道](cooling-air-duct.zh.md)）缩放。 |
| `风门` | `coolingStrength`（0..1，默认 1.0）——只缩风道散热分量（真实 cowl flap）。 |
| `ram(速度)` | **冲压冷却**：10 m/s 以下 ×1.0，线性爬升到 **30 m/s 时 ×2.0**——飞得快免费降温。静态（非物理体）方块 = 1.0。 |
| `f(气压)` | **气压因子**：`气压^0.8`（钳位下限 0.25）。越高空气越稀 → 换热越差 → **高空散热更差**。 |
| `k_water` | **水冷模块的散热贡献**（见下），**加在括号外**——不受冲压/气压影响。 |

### 水冷模块（液体散热）

```
k_water = K_WATER(0.33) × Σ_模块 [ min(液量 / 4000, 1) × 冷却液效率 ] × 回路开度
```

- **不吃冲压、不吃气压**：液体回路不看空气——所以静止、低速、高空这三种「风道最弱」的场景靠它兜底。
- **液量曲线**：≥4000mb 满效；4000mb 以下线性衰减；0mb = 0（平滑，无阈值抖动）。
- **回路开度**：Lua `setWaterCooling(0..1)`（默认 1.0）只缩放 `k_water`；0 = 关闭回路（也不蒸发失液）。
- **沸腾期还有额外散热**（200°C 以上）：`Q_evap = 1.5 × (T − 200)` —— 蒸发带走的潜热从净发热里扣，**不进 `K_total`**，所以同样不吃冲压/气压。这是「用冷却液换高负载下的**紧急**运行」：满罐水 + 4 个满载流体室 ≈ 稳定在 210°C、**约 8.7 分钟**烧完一罐（平台由该斜率锁定，续航由失液速率单独决定）。
- **只对流体引擎生效**：蒸汽引擎温度钉在 `BOILER_T_OPT`，水冷模块对它无效、也不消耗冷却液。
- 完整说明见[水冷模块](water-cooling-module.zh.md)。

## 环境温度（高度→温度）

引擎按**世界高度 Y** 读取环境温度 `T_amb`：

- **物理体**取物理体世界位置 Y（sub-level 原点）；**静态方块**取方块自身 Y。
- **主世界**——Minecraft 尺度分段线性：

| 高度 Y | 环境温度 |
|---|---|
| Y ≤ 63（海平面） | 恒 **20°C** |
| 63 → 200（云层） | 线性 **20°C → 0°C** |
| 200 → 320（世界顶） | 线性 **0°C → −40°C** |
| Y ≥ 320 | 恒 **−40°C** |

- **地狱**：全高度恒 **155°C**——热环境。
- **末地**：全高度恒 **0°C**——冷寂环境。

!!! note "为什么用 Minecraft 尺度而不是真实递减率"
    真实对流层递减率（≈0.0065°C/m）在整个 63→320 世界里只降 ~1.7°C——高度几乎无差异。Minecraft 尺度曲线（海平面→云层→世界顶）让高度真正影响引擎冷却。

## 气压因子（高度→气压）

气压因子与航电传感器共用同一空气模型（Sable 维度大气曲线，锚点间三次 Hermite 插值）：

- 主世界默认锚点：`(−38, 1.5) / (63, 1.0) / (263, 0.4493) / (280, 0.4198) / (320, 0)`——海平面 = **1.0 大气压**，Y≥320 = 0。
- `pressureFactor = max(气压, 0.25)^0.8`。
- 同一气压还驱动**高度自动浓稀**（`autoRichness = 1 + 0.45×(1−气压)`，钳制 [0.75, 1.25]；高气压海平面以下自动稀油）——见[流体燃烧室](fluid-combustion-chamber.zh.md)页。

### 高空玩法小结

高空三件事同时发生：

| 效应 | 方向 | 结果 |
|---|---|---|
| 环境更冷（越高越冷） | 帮助散热 | 平衡温度更低 |
| 空气稀 → 气压因子下降 | 伤害散热 | 平衡温度更高 |
| 自动富油（免费降温） | 帮助散热 | heatFactor 下降，不费油 |

两个冷却效应部分抵消；自动富油是玩家免费的海拔补偿工具（把混合比杆拉到 `m_eff≈1.0` 还能吃到经济系数）。

**散热能力 = 可挂机器的上限**：发热 ∝ 负载，散热差的场合（静止、高空、少气道、风门开小）能维持的负载就低。把负载压到散热能兜住的位置，才是高空巡航的正确姿势。

**水冷模块绕开气压惩罚**：`k_water` 不进 `f(气压)` 括号——高空风道散热被砍到约一半时，水冷仍然是全额。所以高空/静止场景的正确解是「水冷为主、风道为辅」。

## 过热与滞回（流体引擎）

- **T ≥ 220°C** → 引擎硬停（不烧油）并置 `overheated`。
- **T ≤ 200°C** → 解锁并允许重启（滞回避免在阈值附近高频启停）。
- 所有阈值（155°C 经济目标 / 100°C 过冷 / 220°C 过热）都是**引擎固定常量**——不随燃料 / 油门 / 负载变化，如同真实引擎的设计点 / 节温器。
- **热跳闸**：负载长期顶满而散热不足时，引擎会「过热停机 → 冷却到 200°C → 重新出力 → 又过热」周期性循环。这是热保护而不是 bug，解决办法是降负载（减机器 / 降转速）或加强散热（加气道 / 开风门 / 飞得快 / 去低海拔）。
