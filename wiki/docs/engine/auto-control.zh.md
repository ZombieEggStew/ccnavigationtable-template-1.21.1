# 温度与混合比自动控制

引擎核心**内置**一套通用自动控制器：装模组即用，**不需要写任何 Lua 脚本**。只要引擎在运转，它就会自己把**温度稳在经济带（目标 155°C）**、把**实际混合比钉在 0.9**，并在散热不够时自动开风门、开水冷、最后富油兜底。

> 仅对**流体引擎**生效。**蒸汽引擎**不参与——它靠闭式锅炉自调节钉在 155°C、没有混合比/经济区，水冷也对它无效（见[蒸汽动力室](steam-power-chamber.zh.md)）。

## 你管什么，它管什么

自动控制**不碰油门、不碰负载**——那是玩家的两个自由度（见[引擎核心](engine-core.zh.md)）：

| 你负责 | 引擎自动负责 |
|---|---|
| 装燃烧室 / 冷却气道 /（可选）水冷，塞燃料 | 混合比杆（逐 tick 补偿高空自动富油） |
| **油门**（= 输出转速） | 冷却气道**风门**开度（PI+D 控温） |
| **挂多少机器**（= 应力负载） | 水冷模块**回路开度**（模型前馈 + 比例修正） |
| 温度压不住时降载 / 加散热 | **富油兜底**与社会保底（200°C 强制 1.4） |

自动控制只在**散热**这一侧有执行器。负载给得太满、海拔太高或者散热器太少时，它把风门和水冷顶到 100% 也压不住——那时唯一的解还是**降负载**（减机器 / 降转速）或加散热器。

!!! note "每 tick 的位置"
    自动控制在 controller 每 tick 的「蒸汽/流体判定之后、水冷结算之前」运行，且在混合比读取之前 → 它写下的杆值 / 风门 / 水冷开度**本 tick 就生效**（无 1 tick 滞后）。输入用的是上一 tick 的温度（温度更新在 tick 后段），对闭环无实质影响。

## 什么时候该手写 Lua

自动控制的目标是「**基本能用**」——只用温度、模块有无、自动富油系数做决策，**不读玩家的负载/高度/速度策略**。这些情况下建议关掉它自己写：

- 想榨出极限油耗（按高度预先把混合比压到经济窗口边缘、按巡航阶段开关风门）；
- 想让温度长期维持在 155 以外的目标（比如刻意跑凉一点留出加速裕量）;
- 想和自动驾驶联动（爬升/巡航/俯冲用不同的温度目标）。

做法：先 `setAutoControl(false)`，再按需 `setMixture` / `setCooling` / `setWaterCooling`。完整示例见[教练机 v2](../examples/trainer_aircraft_2.zh.md)（用 Lua 控制程序管理引擎温度与混合比，油耗显著下降）。


## 四个执行器（按介入顺序）

| 顺序 | 执行器 | 何时介入 | 目标 / 出力 |
|---|---|---|---|
| 1 | **混合比杆** | 恒定（只要自动控制开着） | 实际混合比 `m_eff = 杆 × autoRichness` 钉在 **0.9** |
| 2 | **风门**（冷却气道） | `T ≥ 145°C` | PI+D 把温度往 **155°C** 拉；`T < 145` 归零保热 |
| 3 | **水冷回路开度** | 风道全开仍不够（模型前馈 > 0）或没装风道 | 补足到达 155°C 还差的散热能力 `k` |
| 4 | **富油兜底**（渐进） | 风道 + 水冷全开（或都没装）仍 `T ≥ 165°C` | `m_eff` 从 1.05 起到 1.4（≈175°C 封顶） |
| — | **硬保底** | `T ≥ 200°C` | 强制 `m_eff = 1.4`——防 220°C 硬停、防冷却液沸腾 |

保热优先：`T < 145°C` 时风门与水冷**一起退场**（只剩混合比），引擎先把自己烧热再谈经济带。

## 混合比：把实际混合比钉在 0.9

```
杆 = clamp( 0.9 / autoRichness , 0.6 , 1.4 )
autoRichness = clamp( 1 + 0.45 × (1 − 气压) , 0.75 , 1.25 )   ← 高度越高空气越稀，天然越浓
```

- **为什么要除 `autoRichness`**：引擎的实际混合比是 `杆 × autoRichness`。高空自动富油（最高 ×1.25）会把实际混合比顶出经济窗口，控制器逐 tick 把杆往下压来抵消——等于**自动完成海拔补偿**。
- **为什么钉 0.9 而不是 1.0**：经济系数混合比窗口是 `0.8 ~ 1.1`，0.9 在其中留出两侧裕度；同时 `m_eff=0.9` 的热因子是 **×1.1**（略热），让地面/低空的小引擎更容易爬进 145~165°C 的经济带。
- **省油效果**：温度 + 混合比双达标后，经济系数渐入 ×0.75——自动控制真正省的就是这 25%。

| 场景 | 气压 | autoRichness | 自动杆值 | 实际 m_eff |
|---|---|---|---|---|
| 海平面及以下 | ≈1.0 | 1.00 | 0.90 | **0.90** |
| Y≈260 高空 | ≈0.45 | ≈1.25 | ≈**0.72** | **0.90** |
| 世界顶 / 极高空 | →0 | 1.25（封顶） | ≈0.72 | **0.90** |

杆值超出 `0.6 ~ 1.4` 时被钳制（极稀空气下无法完全补偿，实际混合比会略偏浓 —— 偏浓的后果只是省油折扣吃不到，不会伤引擎）。

## 风门：PI+D 控温

```
err     = T − 155
积分   += err × 0.05s            （限幅 ±100 °C·s；输出已饱和且误差同向时不累积 → 抗积分饱和）
风门    = clamp( 0.3 + 0.05×err + 0.005×积分 + 0.02×dT/dt , 0 , 1 )
```

| 常量 | 值 | 说明 |
|---|---|---|
| `AUTO_COOL_BASE` | **0.3** | 误差为 0 时的基础开度（155°C 稳态风门 ≈30%） |
| `AUTO_COOL_KP` | **0.05** | 比例：每高出目标 1°C 多开 5% |
| `AUTO_COOL_KI` | **0.005** | 积分：消除稳态残差（增益沿用玩家实飞验证值） |
| `AUTO_COOL_KD` | **0.02** | 微分：抑制温度上升过快时的超调 |
| `AUTO_COOL_INT_MAX` | **100 °C·s** | 积分限幅 |
| `AUTO_WARM_OFF_TEMP` | **145°C** | 经济带下沿（= 155 − 10）：低于此值风门归零、积分清零 |

- **保热分支**：`T < 145°C` 时风门直接 **0**（关掉全部气道散热保热）。还烧不上去就不管了——那是负载/海拔的问题，控制器不负责制造热量。
- **没装冷却气道** → 控制器**不写**风门字段（写了也没有 K_DUCT 分量消费，还会覆盖玩家的手动存值）。

## 水冷：模型前馈 + 比例修正

水冷是**风道饱和后的第二级**。引擎内部本来就有发热 `Q` 和每一项散热的数值，所以不必试探——直接解出「到达 155°C 还差多少散热能力」：

```
kNeed   = Q / (155 − T_amb)                                    // 到目标所需的整机 k
kAirMax = (K_CORE×节数 + K_AMB×运行室数) × f(气压)
        + K_DUCT×风道数 × ram(速度) × f(气压)                    // 风道全开时的 k
waterFF = (kNeed − kAirMax) / waterCoolingCapacity              // 风道够用（kNeed ≤ kAirMax）→ 0
目标开度 = clamp( waterFF + 0.1×(T − 155) , 0 , 1 )
每 tick 最多变化 0.05（缓变，防阶跃）
```

- **为什么必须前馈**：纯比例控制在 `T = 155` 时输出恰好是 0，而水冷往往是**唯一/主要**的执行器 → 稳态必然偏离目标。实测「2 室满载 + 1 个水冷模块」在纯比例下停在 **164°C / 90% 开度**；前馈把工作点直接坐到位（同配置算得 ≈0.99 开度 → ≈155°C），比例项只做小修正。
- **门控（省冷却液）**：只有 `T ≥ 145` 且（前馈 > 0 **或** 没装风道 **或** 风门 ≥ 0.98）才介入。**风道够用时水冷保持 0 开度**——0 开度既不耗冷却液，也不占用引擎的 512 SU/模块 应力（见[水冷模块](water-cooling-module.zh.md)）。
- **自洽**：水冷开度一开就吃应力 → 负载↑ → 发热↑ 且散热↑，前馈每 tick 重算，两三个 tick 内自行收敛到 155°C。
- **没装水冷模块** → 控制器**不写**回路开度字段。
- 水冷本身**只吃很小的冲压/气压份额**，所以静止和高空场景它依旧是主力（见[温度与冷却模型](temperature.zh.md)）。

## 富油兜底（渐进）

当风门和水冷都已开满（或根本没装），温度还在 165°C 以上往上走，控制器就**放弃省油**、开始花油买冷：

```
进入：散热全开（或都没装）且 T ≥ 165°C
目标实际混合比 = clamp( 1.05 + 0.035×(T − 165) , 1.05 , 1.4 )   // ≈175°C 封顶 1.4
退出：T ≤ 150°C，或散热不再全开
硬保底：T ≥ 200°C → 强制 1.4（不等 165 的渐进入口）
```

| 温度 | 目标 m_eff | 热因子 `2 − m` | 说明 |
|---|---|---|---|
| 165°C | 1.05 | ×0.95 | 仍在经济混合比窗口（≤1.1）内，**不会立刻掉经济折扣** |
| 170°C | ≈1.23 | ×0.77 | 发热砍掉 1/4 |
| ≥175°C | 1.40 | **×0.60** | 发热砍掉 40%，封顶 |
| ≥200°C | 1.40 | ×0.60 | 硬保底，只为不触发 220°C 硬停 |

富油是**兜底手段**：`m_eff > 1.1` 后已离开经济混合比窗口，省油的 25% 折扣同时丢掉，油耗按杆值上升。它的意义是「宁可多烧油，也别在巡航中过热停机」。

## 典型场景

| 场景 | 自动控制的表现 |
|---|---|
| 地面静止小引擎（1 流体室 + 2 节核心、25% 负载、无散热器） | 自然散热已够进经济带，风门在低位、水冷保持 0——**什么都不用管** |
| 常规巡航（2 风道、中空、中负载） | 风门在中高开度自动调节，杆值被自动下压（数值见上节「混合比」表） |
| 高空 / 满负载（Y≈260） | 风门逼近全开 → 水冷介入补 k → 仍压不住才开始富油；温度贴着 155~175 走 |
| 末地（环境 0°C） | 目标温差更大、散热更难，风门 + 水冷会顶得更高 |
| **地狱（环境恒定 155°C）** | **经济带基本不可达**：环境温度就等于目标温度，散热温差被抹平，控制器只能全散热 + 富油兜底把温度压住，高负载必然过热 |
| 刚点火 / 停机后重新启动 | 温度 < 145 → 风门 0、水冷 0，先保热暖机；进 145 后才开始控温 |

!!! warning "自动控制不是无限散热"
    它只会**用满已有散热器 + 用油买冷**。冷却气道太少、海拔太高、负载太满叠加在一起时，温度仍会爬向 220°C 硬停。此时应降负载（减机器 / 降转速）或加散热器（气道 / 水冷），而不是等控制器救场。

## 开关与手动接管

| 操作 | 效果 |
|---|---|
| 默认状态 | **开**（`AUTO_ENABLED_DEFAULT = true`；NBT `AutoControl` 持久化，旧存档无记录同样默认开） |
| Lua 调 `setMixture` / `setCooling` / `setWaterCooling` **任一** | **自动关闭**，三个字段全部交还玩家（`getAutoControl()` 变 `false`，goggle 显示「自动控制：关」） |
| `setAutoControl(false)` | 主动关闭（之后引擎不再写任何控制字段） |
| `setAutoControl(true)` | 重新开启：重置积分 / 微分 / 富油档，下一 tick 从自动目标重新接管 |
| 引擎延长 / 换 controller | `autoControl` 开关随控制权一并继承（控制器内部状态重置） |
| 读档 | `autoControl` 落盘；积分、上一 tick 温度、富油档是 transient，读档重置 |

- 手动接管是「**一次性触发**」：只要 Lua 调过一次 `set*`，自动控制就一直关着，直到 `setAutoControl(true)` 或重新组网继承。**想写自己的控制循环，第一行就该 `setAutoControl(false)`**，否则你第一次写参数就等于替它关掉自动控制。
- 蒸汽引擎上自动控制本身不生效（不写任何字段）。

## Goggle 显示

戴 Create goggles 悬停核心：

```
    温度：156.3°C
    总应力输出：8192 SU
    油门：100.0%
    目前转速：256 RPM
    负载：43%
    水冷散热：+0.02
    水冷耗应力：-512 SU
    自动控制：开
```

- **自动控制：开**（绿）/ **关**（灰）——一眼看得出引擎在自动控温还是被玩家接管。
- 自动控制只写字段、**不逐 tick 发包**，靠既有的「离散字段差量 + 1Hz 心跳」同步（与温度等其他 Goggle 数据同一条管道）。

| 常量 | 值 | 含义 |
|---|---|---|

| `AUTO_MIX_EFF` | **0.9** | 自动控制的目标实际混合比 |
| `AUTO_COOL_BASE` / `KP` / `KI` / `KD` | **0.3 / 0.05 / 0.005 / 0.02** | 风门 PI+D 参数 |
| `AUTO_COOL_INT_MAX` | **100 °C·s** | 积分限幅 |
| `AUTO_WARM_OFF_TEMP` | **145°C** | 保热阈值（风门/水冷退场，= 155 − 10） |
| `AUTO_WATER_KP` | **0.1** | 水冷前馈的比例修正增益 |
| `AUTO_WATER_RAMP` | **0.05** | 水冷开度每 tick 最大变化量 |
