# 模块化引擎系统

![engine_core](../img/engine_core.png)

## 背景与意义
现在主流的动力源有如下问题：

- 机械动力的蒸汽锅炉太过笨重
- 航空学的便携引擎输出太低，应力源分散，难以整合
- 其他模组的发动机难以精细控制

本模组的**模块化引擎系统**提供了新的解决方案，是一套模块化多方块 Create 应力网络动力源。

| 方块 | ID | 作用 |
|---|---|---|
| [引擎核心](engine-core.zh.md) | `ccpe:engine_core` | 多方块骨架：核心排成一排组成一条引擎（1×1×N，N≤21），整条共享运行状态；只有 **controller** 输出与决策 |
| [流体燃烧室](fluid-combustion-chamber.zh.md) | `ccpe:fluid_combustion_chamber` | 烧 **其他模组的流体燃料**；**每室 8192 SU**（× 燃料 stress 倍率） |
| [蒸汽动力室](steam-power-chamber.zh.md) | `ccpe:steam_power_chamber` | 烧 **水 + 燃料**产生蒸汽；**每室 4096 SU**；简单稳定、永不过热 |
| [冷却气道](cooling-air-duct.zh.md) | `ccpe:cooling_air_duct` | 散热鳍片 + 可调风门 |

引擎供料辅助方块：

| 方块 | ID | 作用 |
|---|---|---|
| [快速装填流体储罐](fuel.zh.md#quick-fill-fluid-tank) | `ccpe:quick_fill_fluid_tank` | 4000mb 单槽流体存储|
| [快速装填燃料箱](fuel.zh.md#quick-fill-fuel-vault) | `ccpe:quick_fill_fuel_vault` | 单物品类型存储（容量 1024）；蒸汽室的固体燃料源 |

## 两种引擎对照

| | 流体引擎 | 蒸汽引擎 |
|---|---|---|
| 出力 | **8192 SU**/室（× stress）——**容量固定，与油门无关** | **4096 SU**/室——**容量固定，与油门无关** |
| 燃料 | 纯 datapack（`engine_fuel/*.json`） | 纯原版（桶物品熔炉燃烧时长 + 固体物品 burnTime，从燃料箱自动抽取） |
| 混合比/经济区/风门 | 有——玩法核心 | 无（恒 1.0） |
| 温度 | 牛顿冷却 + 过热/过冷管理（引擎固定阈值） | 闭式锅炉自调节，钉在 **155°C**，永不过热 |
| 消耗 | 油耗 ∝ **应力网络负载**（× 杆 × 经济 × 过冷） | **消耗 ∝ 网络负载**（空载按怠速下限燃烧保温），并行燃烧 |
| 复杂度 | 高上限：省油/散热/混合比三重管理 | 简单稳定：点火暖机 → 出力 |

两类燃烧室**物理互斥**：同一台引擎不能混装流体燃烧室与蒸汽动力室（放置被拦截，controller 按多数派仲裁）。

## 三个旋钮：室数定容量、油门定转速、机器定负载

系统解耦成三个互不干扰的量：

| 旋钮 | 决定什么 | 怎么调 |
|---|---|---|
| **燃烧室数量 + 燃料 `stress`** | **应力容量**（每流体室 8192 SU × stress、每蒸汽室 4096 SU）——**恒定，与油门无关** | 加装燃烧室 / 换更好的燃料 |
| **油门** | **输出转速**（转速 = 油门 × 256 rpm；油门 0 = 停机） | Lua `setThrottle` |
| **下游接了多少机器** | **负载**（= 已用应力 / 可提供容量，0~1）——**油耗与发热都按它算** | 增减机器 / 改转速 |

- 空载（下游没接机器）时引擎按**怠速下限 20%** 燃烧保温，不会因为「不转就不烧」而熄火停机。
- 负载越满，烧得越快、越热；靠散热（冷却气道 / 风门 / 飞行速度 / 低海拔）撑住温度，就是这套引擎的驾驶技巧。
- 核心 goggle 的「负载」行显示的是**实际利用率**（空载就是 0%），怠速下限只在燃料消耗与发热的计算里叠加。
